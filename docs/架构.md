# 架构

> 这份文档只写**代码里现在成立的事**。凡是"设计意图"而代码没做到的，
> 一律进 §10「不成立的不变量」，不混在描述里。

## 1. 两层，一条边界

| 层 | 位置 | 行数 | 判据 |
| --- | --- | --- | --- |
| 内核 | `scripts/graph/` | 9.3k | 删掉**任意一个**插件，它仍能编译、仍能启动 |
| 插件 | `plugins/<id>/` | 31k / 42 个 | 可以单独停用、单独替换、单独分发 |

边界用**机器检查**，不靠自觉：

- `test_architecture` 维护白名单，证明"列出来的这些没被内核引用"；
- `--fx-run=diag.blame` 做结构扫描，报「需要动手：内核 N / 插件 M / 装配 K」，当前内核 0 条。

两者互补：白名单只覆盖已知项，`diag.blame` 覆盖「新增了一处引用」这种增量问题。

## 2. 组件与纤维

插件宿主把**每个插件**变成一个 `FxComponent`：

```gdscript
FxComponent = {
    inject:  Array[String],   # 依赖的余效果键（d）
    provide: Array[String],   # 允许写入的键（p）
    apply:   Callable,        # (ctx, config, scope) -> void，效果函数（e）
    on_coeffects: Callable,   # 依赖变化但仍保持激活时的通知
}
```

`ctx.use(component)` 得到 `FxFiber`。`refresh(keys)` 按依赖满足状态做三分类决定：

| 状态 | 动作 |
| --- | --- |
| 未满足 → 满足 | 激活：`apply` 执行，所有副作用登记进 `FxEffectScope` |
| 满足 → 未满足 | 卸载：先撤供给（让依赖者看到不可用），再 LIFO 回放逆操作 |
| 仍满足、键值变了 | 只发 `on_coeffects`（neutral） |

停用人话：**插件的每一件事都必须通过 `scope.add(inverse)` 登记**，否则停用它就撤不干净。
例外是图/算子层的运行时表 —— 那里用 `reset_runtime_tables()` 整体清表兜底（见 §10）。

## 3. 贡献点

插件的全部能力都是**数据或静态 Callable**，不改外壳。完整清单见 `FxPlugin` 文档注释，
常用的是：

| 方法 | 贡献什么 | 谁能用 |
| --- | --- | --- |
| `node_files()` | 节点定义 JSON | `core.graph` 统一加载 |
| `ops()` | `op_id → Callable` | 图求值器 |
| `native_ops()` | `{op, class, thread_safe}` 窄 ABI | `FxNative.bind()` |
| `panels()` / `windows()` | 停靠面板 / 浮动窗 | 外壳停靠区 |
| `commands()` / `menus()` / `menu_items()` | 命令与菜单 | 外壳 |
| `settings()` | 声明式设置项（含 `applies` / `impact`） | `FxSettings` |
| `capabilities()` | 能力键 `{key, apply}`，多 provider 共存 | `FxCapabilities.providers(key)` |
| `status_fragments()` | 状态栏片段 + 装配诊断一行 | 外壳 / 诊断 |
| `graph_access()` | 替换图实现 | `FxGraphFacade` |
| `render_backends()` | 替换渲染后端 | `FxRenderBroker` |
| `node_pickers()` | 替换"添加节点"弹窗 | 蓝图 |

**硬性规则**：内置插件的贡献必须是**静态 Callable**，不能捕获插件实例——
注册表会活过插件对象，实例方法会悬空，引擎退出时段错误。

## 4. 文档写入与内容身份

写入只有三个入口：`mutate()` / `apply_param()` / `apply_path()`；
批量用 `begin_batch()` + `commit_batch(keys)`（没有 `end_batch`）。写前 == 写后**完全静默**。

内容身份：

```
content_key() = 世代 × 2^20 + 内容修订
```

`positions` / `size` / `selection` / `time` **不算内容**。于是拖动节点、缩放分组、
改选中都不换桶、不重画——这条由 `_on_store_changed` 的 `_is_layout_only` 闸门保证，
并由 `test_editor_ui` 的「拖动节点不改变缓存指纹」守着。

**桶之外还有一层身份：每一帧自己记着「我是哪份内容算出来的」**
（`FxFrameCache.identity`，见 `put(..., identity)`）。桶按指纹重建，但指纹是
拓扑 + 参数 + 画布的**合成哈希**，而预渲染线程与主线程是并发的 —— 第 N 版文档
算出的帧可以在这一桶里活到第 N+1 版。分发前一律 `accepts(index, content_key)`：

| 场景 | 身份不符时 |
| --- | --- |
| 播放供帧 | 当未命中，交给急件重算 |
| 停播定格 | 拒绝贴图，改为请求一次实时求帧 |
| 暂停态贴帧 | 不贴，等这一格被当前内容重算 |

磁盘恢复的帧身份是 `-1`（不记）：桶目录本身就是内容指纹，属于这一桶即属于这份内容。
没有这一层时，屏幕上会出现一张「绿色就绪、谁也不认领」的旧图 —— 表现正是
「改了参数没效果、画面不回来」，而且不报错。

## 5. 渲染管线

```
文档变更 ──► _on_store_changed（三道闸门）
                │
                ├─ 布局键 → 直接返回
                ├─ 内容身份未变 → 返回
                └─ 按 keys 分档失效 → invalidate(kind, source)
                        │
       ┌────────────────┼─────────────────┐
   同步路径          工作线程            预渲染（2–6 线程）
       └────────► 同一份 compile_plan ◄──┘
                        │
                    _publish → 帧缓存 / 显示层 / 节点小图
```

- **三条路径共用一份 IR 计划**：`FxRenderService._plan_for_current_doc()` 按
  `(content_key, 预览根)` 缓存，失配（ids_hash 变了）整份作废。
- **失效三档**：`content` 换桶；`derived` 丢执行器静态表、样张、显示层但**保留精确帧**；
  `display` 只丢显示层。设置项用 `impact` 声明自己属于哪一档。
- **精确性由算它的那一档质量决定**：结果自带 `frame_quality` / `frame_operator_quality`，
  归档判定看这两个字段，不看"此刻在不在播"。
- **播放只读缓存**：每 `process` 帧号至多 +1；`state == EMPTY` 才挂起；
  `STALL_LIMIT = 0.35s`；归档到新绿格后 `_emit_cache()`（0.25s 节流）。
- **拖时间轴也只读缓存**：纯时间变化（`keys == ["time"]`）先查这一格有没有精确帧，
  有就当场接管、**不排求值**。拖动时每个鼠标事件都是一次 `set_time`，
  而求值一帧上百毫秒 —— 排队求值永远追不上指针，用户看到的就是「拖了没反应」。
  在途的实时结果若算的是**别的时刻**，归档进缓存但不上屏（否则拖完会往回跳一帧）。
- **参数面板的时间刷新只碰「会随时间变」的行**：打了关键帧的、被连线驱动的。
  示范工程 103 个节点，从前每次 `set_time` 都要重设几百个 slider / SpinBox / 文本，
  实测一步 110 ms —— 这是「拖不动」的另一半原因，和求值无关。
- **显示通道唯一** `_gpu_display(index)`，键 = 内容身份 + 帧号 + 画布尺寸 + 显示倍率。

### 5.1 画布尺寸：帧尺寸就是桶的布局

`frames.fxc` 是「帧号 × 定长 = 偏移」的紧密文件。**帧尺寸不是显示参数，是文件格式的一部分**：
一张 128×128 的图混进 192×108 的桶，整个文件从此错位。所以尺寸有三层互不依赖的防线：

| 层 | 规则 | 违反时的表现（都真实发生过） |
| --- | --- | --- |
| 定桶 | 「桶的帧尺寸 ≠ 当前画布」本身就是换桶理由，**不看** `_cache_dirty` | 改画布后屏幕永远停在旧尺寸，桶里却「全绿」 |
| 入库 / 取出 | `put()` 拒绝异形帧；`fetch()` **连内存热层**也要校验尺寸 | 内存里那张旧尺寸图冒充命中，看着正常、尺寸不对 |
| 上屏 | `_publish()` / `_publish_cached()` 各有一道尺寸闸门，不符就丢弃并重排 | 在途结果算的是上一版画布，贴上去就是「没反应」 |

三道防线互不依赖是刻意的：前两道管数据，第三道管像素。**任何一条失效，另外两条仍然挡住坏帧**。
被闸门挡下的发布会记一条 `publish-drop`（含 `got` / `want`），见 `docs/诊断与归因.md` §6。

**画布只有一个存放处：`meta.canvas`。** 输出节点上那两个「画布宽 / 画布高」是它的
**视图**（节点定义里声明 `binds: canvas.width`），不是第二份数据：

| 位置 | 规则 |
| --- | --- |
| 节点定义 | 参数带 `binds`；控件显示文档值，不显示自己的值 |
| 写入 | `FxGraphAccess.doc_apply_path` 接管：写它 = 写 `meta.canvas`，节点上永远不留值 |
| 算子 | `output.final` 一律按 `ctx.canvas` 出图 |
| 装载 | 旧工程里的遗留覆盖值在打开时清掉 |
| 诊断 | `diag.blame` 第 7 条判据：绑定参数在文档里必须存 0 |

这不是洁癖：节点一旦能说出 256×108 而文档仍是 192×108，输出帧就会被上表第三道闸门
**整帧丢掉**，每一帧都丢 —— 画面停在旧图上、不报错、日志干净，看起来就是「渲染器坏了」。

### 5.2 动态质量：先给一张草稿，再被精确帧替换

精确帧一次要几十到上千毫秒，这段时间屏幕上是空白。「没缓存就看不到预览」不是性能问题，
是**没有中间档**。动态质量补上这一档，而且是**两条**通道：

```
内容变化（改参数 / 改画布 / 打开工程）
   │
   ├─ ① 草稿趟（预渲染通道，6 线程，1/8 画布）
   │      整段按帧号铺一遍 → 写进「垫图层」（黄格）→ 播放立刻有图可贴
   │
   └─ ② 精确趟（同一批线程，全画布）
          逐帧把黄格换成绿格；用户已经看到的动画在这期间一直是「有画面的」

当前帧另外有一条 ③ 单帧草稿线程（1/8 → 1/4 → 1/2 阶梯）：
只服务「停下来改一个参数」的那一眼，不等预渲染的 0.12s 起跑 + 队列。
```

**为什么草稿趟比单帧草稿重要**：播放的推进条件是「下一帧有没有图」
（`state == EMPTY` 才挂起）。只给当前帧出草稿，播放照样一帧一帧等精确帧；
把整段先铺成垫图之后，播放可以按 30fps 走完整段 **低画质** 动画，
精确帧在后台逐格替换 —— 这正是「最后逐步使用目标质量替换」。

四条硬边界（不是优化，是它存在的合法性）：

- **只服务显示**：垫图写进帧缓存时 `exact = false`（`STATE_PENDING`，黄格），
  永不落盘、永不参与「这一帧好了没」。`put()` 里还有一条反向保护：
  **精确帧已就绪时，垫图连内存都不许进**。
- **不跑汇点**（`FxGraphRunner.skip_sinks`）：汇点里有 `io.export_*` 的写文件副作用，
  草稿随时可能被丢弃，拿它触发导出就是让一次预览写满磁盘。
- **不进显示缓存**：`_gpu_display(approx = true)` 直接返回、不查也不写缓存。
  否则糊图会以「内容 + 帧号」的名义被登记，之后精确帧发布时直接命中它 ——
  **画质就永远上不去**，而每一格看起来都正常。
- **结果自带身份**（内容身份 + 帧号 + 播放世代）：不匹配就丢。晚到的草稿
  不许盖掉已经上屏的精确帧，也不许把播放头往回拽一帧。

内存护栏：垫图存在帧缓存里（定长布局要求画布尺寸），整段字节数超过内存预算的 60%
时不跑草稿趟 —— 那种尺寸下垫图会互相挤掉，变成「贴一张丢一张」，比没有更糟。
此时只有 ③ 单帧草稿兜底。

### 5.3 标尺四色：缓存状态 vs 调度事实

`cache.state()` 只回答一个问题：**这一格能不能用**（`EMPTY` / `PENDING` / `READY`）。
标尺要的是另一个问题：**这一格现在是什么状况**，所以另有 `cache.display_state()`：

| 值 | 颜色 | 含义 | 数据来源 |
| --- | --- | --- | --- |
| 0 | 红 | 没算过 | `_states` |
| 1 | 黄 | 只有垫图（草稿 / 播放档） | `_states == PENDING` |
| 2 | 绿 | 精确帧已缓存 | `_states == READY`（压过一切） |
| 3 | 橘 | 有线程正在为这一格干活 | 在飞登记表（`set_rendering`） |

橘色是**瞬时事实**，所以它不落盘、不参与任何判断，而且整批覆盖（不是逐格置位/清除）：
漏清一格就会永远橘着，比不显示更糟。它的来源只有两个，都是调度器自己的账本，不猜 ——
**预渲染派发出去的帧号**与**单帧工作线程手上那一帧**；缩略图趟在飞时**不算**
（那一趟不产出可缓存帧，标橘会让用户以为整段正在补帧）。

## 6. 剪枝与 IR

`core.compile` 产出**纯数据计划**（不是字节码）：

| 字段 | 含义 |
| --- | --- |
| `order` | 拓扑序 |
| `live` / `dead` | 判活结果（Live = Reachable(output) ∪ 预览根 ∪ 汇点 ∪ 执行流节点） |
| `sinks` | 汇点（6 个 `godot.export` 导出节点有写文件副作用，一个都不能剪） |
| `constants` / `fold_params` | 常量折叠（只收纯标量，**绝不预算 Image**） |
| `type_errors` / `cycles` | 编译期可报的错误 |
| `plan_tracks` / `clock_nodes` | 帧指纹分段与时钟闭包 |
| `ids_hash` | 校验：id 集合变了整份计划作废 |

注入方式：`capabilities()["graph.compile"]` → `FxCapabilities.providers()`。
**不要用 `services()`**——外壳会把服务工厂当实例创建。

停用 `core.compile` 时计划为空，求值器回到原行为（拉取式全图求值）。

## 7. 分辨率档

节点可选字段 `res_scale` ∈ {1, 0.75, 0.5, 0.25, 0.125}：**本节点及其上游**按该倍率求值，
输出交给下游时还原全尺寸；**输出/导出尺寸永不变**。

- 传播是**区段模型**：声明者向上游走，遇另一个声明者即停；
- 另有「1.0 需求传播」：从 output / 汇点 / 预览根向上游走，保证共享上游不被旁支拖下水；
- 像素单位参数按 `unit: "px"` 乘 `ctx.eval_scale`，否则不是"画质略降"而是"效果变了"；
- 输出节点与 `evaluate_always` 汇点**拒绝**降档，理由写在 `scale_report.refused`。

实测（示范工程）：192² 下 0.5 档 2.40×、0.25 档 3.59×；512² 下 2.60× / 4.19×。

## 8. 原生像素内核（插件形态）

`plugins/pixels.native/` 是一个**完整插件**：清单、脚本、C++ 源码、库、描述文件都在里面。

```
plugins/pixels.native/
├── plugin.json                 # 声明 native.library 与 provide
├── plugin.gd                   # activate → 启用桥；deactivate → 回落 GDScript
├── src/{point,warp,blend,edge,gen}_ops.cpp
├── src/common/{prelude,pixel_math,image_access,row_runner,counters}.h
├── src/register_types.cpp      # 注册 5 个类
├── SConstruct / build.sh       # 两种构建路径
└── native/                     # 构建产物（gitignore）
```

**ABI 边界**：C++ 侧只交换基础类型（`Image` / `Color` / `Packed*Array` / `Dictionary`），
不 include 任何 GDScript 类型，所以能独立编译、独立分发。

**失败粒度**：五个算子族是五个类。某一族缺失时只有那几个算子回落 GDScript。
`FxNativeBridge.abi_report()` 报逐族实况，装配诊断会打印"5/5 族在场"。

**精度纪律**（两条硬边界，`test_pixel_native` 的 97 条逐字节断言守着）：

1. 直接读字节 = double 语义；走 `get_pixel/set_pixel` 要先过 float32
   （`norm_byte_f32` / `pack_trunc_f32`）；
2. `Image.set_pixel` 是**截断**不是四舍五入（`uint8_t(CLAMP(r*255))`），
   着色算子差这一步就是 1/4 字节差 1。

## 9. 扩展点：换掉任何一层

| 想换 | 做法 | 不改什么 |
| --- | --- | --- |
| 图求值实现 | 贡献 `graph_access()` | 编辑器、面板、文档格式 |
| 渲染后端 | 贡献 `render_backends()` | 求值器、缓存策略 |
| 呈现器（预览怎么显示） | 实现 `FxRenderHost` 并注册到 broker | 外壳 |
| 节点面板 | 贡献 `node_pickers()` | 蓝图视图 |
| 皮肤 | 贡献 `skins()` | 界面结构 |
| 语言 | 贡献 `locales()` | 任何代码 |

## 10. 不成立的不变量（别按它们写代码）

1. **「组件移除后副作用完全撤回」只在 UI/服务层成立**。图与算子层的运行时表
   由 `FxGraphAccess.reset_runtime_tables()` 整体清空，是兜底不是逆操作。
2. **「同一键只能被提供一次」不成立**。`provide()` 不检查占用，后写覆盖先写
   （`render.gpu` 覆盖 `image.blur` 依赖这一点）。
3. **「值变才通知」不成立**。`set_value()` / `provide()` 不比新旧值，写就通知。
4. **「输出预览永不降采样」已按维度拆开**（`app 0.0.12`）。`output_downscale`
   只约束**归档帧与导出**（恒 false，内核钉死）；显示通道另有 `display_scale`
   （1.0 / 0.5 / 0.25），只缩「贴到屏幕的那一张」。缓存里存的仍是全分辨率原图，
   导出的仍逐像素一致 —— 所以这条不再算「不成立的约束」，而是两条各自成立的约束。
5. **「内核零插件类名」靠工具证明，不靠编译器**。删掉某插件后仍能启动，
   但基座里的 `FxGraphFacade` 会回落到空实现 —— 那是**设计上的降级**，不是等价功能。
