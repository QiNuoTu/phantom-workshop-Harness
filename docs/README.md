## 两条阅读顺序

- **想改代码**：架构 → CLAUDE.md（不变量）→ 插件开发（若加能力）→ 诊断与归因（出问题时）。
- **想发版**：版本策略（§6 发布闸门）→ 性能口径（数字要有口径）→ `bash tools/run_tests.sh` + `python tools/check_docs.py`。

## 维护规则

1. **只写代码里现在成立的事**。设计意图、未兑现的保证，单独列在"不成立的不变量"一节，
   不要混在描述里（`架构.md` §10 就是干这个的）。
2. **数字必须能复算**：由 `python tools/check_docs.py` 核对的（版本 / 插件数 / 节点数 /
   套件数 / 基座行数 / 断言数）直接写；其余数字写清"用什么命令取的"。
3. **新增文档要登记到这张表**，并在 README 的「文档地图」里给一行；
   `check_docs.py` 会检查相对链接是否存在，链接断了门禁就红。
