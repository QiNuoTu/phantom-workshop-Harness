# 插件开发

> 写一个插件 = **加一个目录**。不改外壳、不改求值器、不改基座。
> 如果做不到这一点，说明该扩的是契约，不是在一处 `if plugin == "xxx"`。

## 1. 最小插件

```
plugins/hello.world/
├── plugin.json
└── plugin.gd
```

`plugin.json`：

```json
{
	"id": "hello.world",
	"name": "示例插件",
	"version": "0.1.0",
	"contract": ">=0.1.0 <0.2.0",
	"description": "最小可运行插件：贡献一个命令与一个设置项",
	"script": "plugin.gd",
	"inject": ["kernel.graph"],
	"provide": { "plugin.hello.world": "0.1" }
}
```

`plugin.gd`：

```gdscript
extends FxPlugin

func commands() -> Array[Dictionary]:
	return [{
		"id": "hello.say", "label": "示例：打个招呼",
		"handler": _say,          # 必须是静态 Callable
	}]


static func _say(_ctx: Dictionary) -> void:
	print("hello from plugin")


func settings() -> Array[Dictionary]:
	return [{
		"id": "hello.verbose", "label": "示例：啰嗦模式",
		"type": "bool", "default": false,
		"applies": "immediate",       # 什么时候生效
		"impact": "none",             # 生效时要作废什么（none / display / derived / content）
	}]


func status_fragments() -> Array[Dictionary]:
	return [{
		"id": "hello.badge", "order": 90,
		"handler": _badge,
		"diagnostic": _diag,
	}]


static func _badge(_stats: Dictionary) -> Dictionary:
	return {"text": "", "tone": ""}


static func _diag(_service: Variant) -> String:
	return "示例插件 hello.world：已加载"
```

## 2. 清单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✔ | 唯一标识，与目录名一致（诊断、设置、依赖全用它） |
| `name` | ✔ | 显示名 |
| `version` | ✔ | 插件自己的迭代号，从 `0.1.0` 起 |
| `contract` | ✔ | 能装在这版内核上的区间，见 [版本策略](版本策略.md) |
| `script` |  | 不写则用空 `FxPlugin`（只有清单也能"占位"） |
| `inject` |  | 依赖的余效果键；**不满足就不激活** |
| `provide` |  | 允许写入的键；别人的 `inject` 可以指向它 |
| `native` |  | `{"library": "xxx.gdextension"}`，宿主在 `activate()` 前加载 |
| `icon` / `color` / `category` |  | 插件中心的外观 |
| `enabled` |  | 默认启停（用户配置会覆盖） |

扫描根按优先级：`res://plugins` → `user://plugins` → `<exe>/plugins`。
同 id 先到先得，所以用户可以用同 id 目录**覆盖**内置插件做实验。

## 3. 贡献点

全部是数据或**静态 Callable**。完整签名见 `scripts/graph/plugins/fx_plugin.gd` 的文档注释。

| 方法 | 用途 | 注意 |
| --- | --- | --- |
| `node_files()` | 节点定义 JSON | `op` 必须能在算子表里查到，否则启动即报 |
| `ops()` | `op_id → Callable` | 后登记覆盖先登记的**是有意设计** |
| `native_ops()` | `{op, class, thread_safe}` | 需要 C++ 侧实现 `fx_exec(inputs, params, env)` |
| `time_dependent_ops()` | 声明哪些 op 读时钟 | 声明了就不进跨帧缓存 |
| `panels()` / `windows()` | 停靠面板 / 浮动窗 | `factory(ctx) -> Control` |
| `commands()` / `menus()` / `menu_items()` / `toolbar()` | 命令与菜单 | 命令 id 全局唯一 |
| `settings()` | 声明式设置 | 必须写 `applies` 与 `impact` |
| `capabilities()` | 能力键，多 provider 共存 | 消费方用 `FxCapabilities.providers(key)` |
| `status_fragments()` | 状态栏片段 + 装配诊断一行 | 让"这个能力在不在"变成可查的事实 |
| `graph_access()` / `render_backends()` / `node_pickers()` | 替换核心实现 | 默认实现是空壳 |
| `skins()` / `locales()` / `param_kinds()` / `exporters()` / `drop_handlers()` / `clocks()` | 外观、语言、参数控件、导出、拖入、时钟 | 

**面板的 `order` 决定两件事**：标签条里的先后，以及**该停靠区的默认面板**
（可见面板里 `order` 最小的那个）。它不由「谁先注册」或「谁最后被重放可见性」决定 ——
右侧区的预览 `order = 10`、插件中心 `order = 900`，所以打开软件看到的是预览。
想让自己的面板默认可见，就把 `order` 写小，而不是去抢焦点。

**静态 Callable 规则**：内置插件的贡献登记进静态注册表，会活过插件实例。
写 `self.method` 会让引擎在退出时崩（表现为 `--headless` 下段错误）。

## 4. 生命周期与可逆性

```
扫描目录 → 读清单 → 建 FxFiber → 依赖满足才 activate() → 收集贡献
                                        │
                              停用 / 依赖丢失 / 重载
                                        ▼
                         先撤供给 → LIFO 回放逆操作 → deactivate()
```

`activate()` 里做的每一件事都要能被撤回：**要么登记逆操作，要么交给注册表账本**。

```gdscript
func activate() -> void:
	# 自己 new 的东西自己登记（宿主会把 scope 交给你，见 FxPlugin.apply 约定）
	FxNativeBridge.set_enabled(true)          # 静态开关，deactivate 里复位


func deactivate() -> void:
	FxNativeBridge.set_enabled(false)
```

注册表贡献（算子、面板、命令…）不用手动撤 —— 宿主按 owner 逐条撤销。
**自己 `new` 的 Node、连的信号、开的文件、改的全局静态状态**必须自己处理。

## 5. 原生插件（C++）

两条路，别混：

| 方式 | 适用 | 边界 |
| --- | --- | --- |
| `native_ops()` 窄 ABI | **整个算子**在 C++ 里 | C++ 实现 `fx_exec(inputs, params, env) -> Dictionary`，只交换基础类型 |
| 自带库 + 桥（`pixels.native` 的做法） | **只有最内层循环**在 C++，语义仍在 GDScript | 桥按族取类，缺席回落 |

`pixels.native` 是第二种的完整样例：

1. `plugin.json` 写 `"native": {"library": "pixels_native.gdextension"}`；
2. `register_types.cpp` 用 `GDREGISTER_CLASS` 注册 5 个族类；
3. `plugin.gd` 的 `activate()` 只做"启用桥"，`deactivate()` 做"回落"；
4. GDScript 侧算子照旧，只在最内层调 `FxNativeBridge.hue(...)` 一类函数。

构建（Windows / MSVC，不需要 SCons）：

```bash
bash plugins/pixels.native/build.sh template_debug
```

三个开关少一个就会以"看不懂的样子"失败，脚本里已写好：

- `-Zc:__cplusplus`：MSVC 默认把 `__cplusplus` 报成 199711L；
- `-DTYPED_METHOD_BIND`：与 godot-cpp 的编译开关一致；
- `-MT`：godot-cpp 静态库是 `/MT` 编的。

## 5.0 参数控件（`param_kinds`）的三条纪律

| 纪律 | 为什么 |
| --- | --- |
| **kind 名带插件前缀**（`tone.curve`、`asset.texture`），别用 `curve` / `slider` 这类通用词 | kind 是全局命名空间，后注册覆盖先注册。通用词迟早被两个插件抢 |
| **写入要合批**：拖动类交互攒 ~0.1s 一次 `ctx["set"]`，不要把每个鼠标事件都写进文档 | 每次写入 = 一条撤销记录 + 一次换桶 + 整段缓存重建。实测一次拖动能刷几十次 |
| **不要在 `sync()` 里覆盖用户正在改的值** | `sync()` 是"把文档读回来"，自家有未落盘的改动时读回的是旧值，会把手感变成"点弹回去" |

参考实现：`plugins/fx.tone/fx_curve_widget.gd`（曲线控件，含 `_dirty` + `flush()` 的合批骨架）。
数值型控件由基座提供（`FxWidgetRegistry`），插件自带的控件一律按上面三条来。

## 5.1 插件内部的多文件怎么互相引用

一个插件里想把逻辑拆成多个 `.gd` 时（面板、参数控件、诊断命令…），
**用 `preload` 的 `res://` 全量路径**。真实例子（`plugins/fx.keying/plugin.gd`）：

```gdscript
const KEY_COLOR := preload("res://plugins/fx.keying/fx_keycolor_widget.gd")
const KEYER_PANEL := preload("res://plugins/fx.keying/fx_keyer_panel.gd")

func param_kinds() -> Dictionary:
	return {"keycolor": KEY_COLOR.build}

func panels() -> Array[Dictionary]:
	return [{"id": "fx.keying.stage", "factory": KEYER_PANEL.build, ...}]
```

被引用的那份脚本**不写 `class_name`**，全部导出静态函数：

```gdscript
# fx_keycolor_widget.gd —— 不写 class_name
extends RefCounted

static func build(ctx: Dictionary) -> Dictionary:
	return {"control": column, "sync": sync}
```

三条踩过的坑，都写在这里省下一次调试：

| 写法 | 结果 |
| --- | --- |
| `const OPS := preload("fx_ops_keying.gd")`（相对名） | 解析成 `gdscript://fx_ops_keying.gd`，启动即报 `Preload file ... does not exist` |
| 给被引用的脚本加 `class_name` 再引用 | 第一次无头运行解析不到（缓存里还没有），除非先 `--headless --editor --quit` |
| `const X := preload("res://plugins/<id>/xxx.gd")` | ✔ 编译期解析、不依赖类名缓存 |

路径里写死插件目录名没问题：**宿主按目录名 == `plugin.json` 的 `id` 扫描**，这个目录名不会变。

面板 / 参数控件 / 诊断命令的入口也能这样传：`"factory": KEYER_PANEL.build`、
`"handler": PROJECT_REPORT.cmd_report` —— 它们都是**静态函数**，不会捕获插件实例，
因此停用插件时不会留下悬空 Callable（§3 的硬性规则同样适用）。

## 5.2 把算子写成原生（`native_ops`）

窄 ABI 的另一条路：**整个算子**都在 C++ 里，GDScript 侧只声明"哪个 op 由哪个类实现"。
`plugins/fx.native-kit/` 是完整样例（5 个族类 / 28 个算子）。

```gdscript
# plugin.gd —— 没有 ops()，只有 native_ops()
func native_ops() -> Array[Dictionary]:
	return [
		{"op": "key.chroma_pro", "class": "FxKitKey", "thread_safe": true},
		{"op": "channel.extract", "class": "FxKitChannel", "thread_safe": true},
	]
```

```cpp
// 一个族类承载一族算子，靠 env["op"] 分派
Dictionary FxKitKey::fx_exec(const Dictionary &inputs, const Dictionary &params,
                             const Dictionary &env) {
	String op = text(env, "op", "");
	if (op == String("key.chroma_pro")) { return op_chroma_pro(inputs, params); }
	...
	return empty_out();
}
```

清单里写库路径，宿主在 `activate()` 之前加载：

```json
"native": { "library": "fx_native_kit.gdextension" }
```

### 四条必须守住的东西

| 规则 | 为什么 |
| --- | --- |
| **一个族一个类**，不要一个巨型类 | 某族编不出来时只丢那几个算子；停用插件只撤回自己绑的 |
| 不持跨帧可变状态 | 工作线程会反复调同一个实例。真要缓存就自己加锁并声明 `thread_safe: false` |
| **循环里不许比较 `String`** | `mode == String("red")` 会让每像素构造一次字符串：实测把 0.6 ms 拖到 8.6 ms |
| 每像素 ≤ 135 ns / 参考画布 ≤ 3 ms | 超了就别写逐像素实现；`tests/test_fx_budget.gd` 会红 |

### 不留 GDScript 回落

`pixels.native` 那套是"有回落的全工程工具"（缺库就退回 GDScript，画面一样、只是慢）。
`fx.native-kit` 反过来：**它是唯一实现**。理由写在 `docs/调色抠像套装.md` §5.1 ——
两条路径意味着只有一条被测，另一条迟早漂移，而且"慢十倍但能跑"会让用户误判性能。

因此这类插件要 `inject` 原生包的 key：

```json
"inject": ["kernel.graph", "plugin.fx.native-kit"]
```

这样原生包缺席时节点插件本身不激活，`diag.blame` 会报「插件未激活（依赖未满足）」，
而不是让 28 个节点各自报「算子没有实现」——后者会把人引向错误的排查方向。

## 6. 测试与归因

| 要证明什么 | 用什么 |
| --- | --- |
| 你的算子算得对 | 加断言到 `tests/test_<域>.gd`；有原生实现的跑"开关两跑逐字节比对" |
| 停用后仍能启动 | 删掉目录跑 `--fx-diagnose`，看"跳过"是不是只剩预期的那条 |
| 归属清楚 | `--fx-run=diag.blame`，`需要动手` 里不该出现你 |
| 缓存没被你搞乱 | `--fx-run=diag.cache`，看 `invalidate` 的档位有没有报高 |

## 7. 常见错误

| 现象 | 原因 |
| --- | --- |
| `跳过 res://plugins/x：缺少 plugin.json` | 目录里没有清单（原生源码目录也会被扫，别把源码放在 `plugins/` 下当插件） |
| 插件脚本无法加载 | 新的 `class_name` 还没进全局类名缓存。要么跑 `--headless --editor --quit` 重建缓存，要么**别用 `class_name`**，改用 §5.1 的 preload 写法 |
| 启动即报「节点定义了但 op 查不到」 | `nodes*.json` 里的 `op` 拼错，或算子贡献没生效 |
| 停用后画面变了 / 崩 | `activate()` 里改的全局状态没有在 `deactivate()` 复位 |
| 一改设置整段缓存重建 | `settings()` 的 `impact` 写成了 `content`（或没写，回落 `content`） |
| 退出时段错误 | 贡献了实例方法 Callable；改静态 Callable |
