## 1. 十分钟上手

一个插件的最小闭环是 **两个文件**：

```
plugins/my.glow/
├── plugin.json     清单：我是谁、我依赖谁、我提供什么
├── plugin.gd       入口：我做哪些贡献
├── nodes.json      节点定义（可选）
└── ops.gd          算子实现（可选）
```

`plugins/glow/` 就是这样一个完整插件（本手册所有示例都可以在仓库里找到对应实现）。  
它新增了 `image.glow` 节点，没有改 `FxCatalog`、`FxGraphRunner`、编辑器任何一行。

**plugin.json**

```json
{
	"id": "my.glow",
	"name": "辉光",
	"version": "1.0",
	"description": "为图像添加柔和的外发光",
	"script": "plugin.gd",
	"inject": ["kernel.graph", "plugin.core.pixels"],
	"provide": {"plugin.my.glow": "1.0"}
}
```

**plugin.gd**

```gdscript
extends FxPlugin

func node_files() -> Array[String]:
	return [local("nodes.json")]

func ops() -> Dictionary:
	return {&"my.glow": FxMyGlowOps.apply}
```

**nodes.json**

```json
{
	"category": "图像/合成",
	"nodes": [{
		"id": "my.glow",
		"label": "辉光",
		"desc": "降采样模糊后滤色叠加。",
		"op": "my.glow",
		"inputs":  [{"id": "image", "label": "图像", "type": "image"}],
		"outputs": [{"id": "image", "label": "图像", "type": "image"}],
		"params": [
			{"id": "radius", "label": "半径", "kind": "int", "default": 4, "min": 1, "max": 32},
			{"id": "amount", "label": "强度", "kind": "float", "default": 0.6, "min": 0.0, "max": 1.0}
		]
	}]
}
```

**ops.gd**

```gdscript
class_name FxMyGlowOps
extends RefCounted

static func apply(ctx: FxEvalContext, _node: Dictionary, _def: FxNodeDef,
		inputs: Dictionary, params: Dictionary) -> Dictionary:
	var source: Variant = inputs.get("image")
	if not source is Image:
		return {"image": FxImageUtil.new_canvas(ctx.canvas)}
	var radius := clampi(int(params.get("radius", 4)), 1, 32)
	var amount := clampf(float(params.get("amount", 0.6)), 0.0, 1.0)
	var image := source as Image
	var out := image.duplicate()
	var small := image.duplicate()
	var factor := clampf(float(radius) * 0.9, 1.35, 12.0)
	small.resize(maxi(1, int(round(float(image.get_width()) / factor))),
		maxi(1, int(round(float(image.get_height()) / factor))), Image.INTERPOLATE_BILINEAR)
	small.resize(image.get_width(), image.get_height(), Image.INTERPOLATE_BILINEAR)
	FxImageUtil.blend_image(out, small, Vector2.ZERO, "screen", amount)
	return {"image": out}
```

放到 `plugins/` 下，重启（或插件中心里启用）就出现在「添加节点」面板里了。

**唯一必须记住的一条**：`ops()` 返回的 Callable 用**静态函数**（`FxMyGlowOps.apply`），  
不写 `self.apply`。静态函数无状态、热重载不带残留、能被测试直接调。理由见  
[14. 硬性规则](#14-硬性规则)。

## 2. 插件的形状

### 2.1 目录

| 位置                       | 用途             | 何时生效   |
| ------------------------ | -------------- | ------ |
| `res://plugins/<id>/`    | 开发期直接读工程里的插件   | 编辑器运行时 |
| `<exe 同级>/plugins/<id>/` | 发行版；用户可自己增删、替换 | 导出后运行  |
| `user://plugins/<id>/`   | 用户目录，优先级最高     | 导出后运行  |
| PCK 内那份                  | 上面几处都找不到时的兜底   | 导出后运行  |

扫描顺序即上面的顺序；**同一个 id 只认第一个**。插件产物不用进 PCK 也能跑，  
打包脚本按插件 id 镜像到 `dist/plugins/`。

### 2.2 plugin.json 全字段

| 字段                    | 类型       | 说明                                                                  |
| --------------------- | -------- | ------------------------------------------------------------------- |
| `id`                  | string   | 唯一标识。缺省取目录名。**改名等于换插件**（设置、布局、禁用列表都按 id 记）                          |
| `name`                | string   | 显示名，会过一遍语言包                                                         |
| `version`             | string   | 字符串，不参与比较，只用于展示和依赖报告                                                |
| `description`         | string   | 一句话说明，显示在插件中心                                                       |
| `script`              | string   | 入口脚本，默认 `plugin.gd`                                                 |
| `inject`              | string[] | **依赖声明**（见 8.1），只影响加载顺序，不传对象                                        |
| `provide`             | object   | 我提供哪些键给别人的 `inject` 用，值写版本号                                         |
| `native`              | object   | `{"library": "native/xxx.gdextension"}`，见 [13](#13-原生算子gdextension) |
| `icon`                | string   | 插件图标，相对插件目录；可以是图片也可以是 `.gif`                                        |
| `icon_file`           | string   | 图标文件（优先于 `icon`）                                                    |
| `icon_anim`           | object   | `{cols, rows, fps}`：把图标当精灵表播动画                                      |
| `color`               | string   | 主题色，`#rrggbb`                                                       |
| `author` / `homepage` | string   | 展示用                                                                 |
| `category`            | string   | 插件中心分组，默认「插件」                                                       |

`plugin.json` 可以不要：目录里有 `plugin.gd` 就按目录名注册。

### 2.3 plugin.gd 生命周期

```gdscript
extends FxPlugin

func activate() -> void:      # 注册贡献之前
	pass

func deactivate() -> void:    # 插件被停用 / 引擎退出
	pass
```

真正的加载顺序：

```
扫描目录 → 读清单 → 建 fiber（写依赖边）→ 拓扑排序
  → new() 实例 → setup() → activate()
  → 收集 node_files / ops / panels / ... 每项都登记一条可逆贡献
  → runtime_plugin 把实例保活到停用为止
```

插件被停用时，宿主**按登记的逆序**撤回它的全部贡献：节点消失、面板关闭、  
命令从菜单里拿掉、语言包回退。你不需要写清理代码——**只要不自建全局状态**。

### 2.4 实例活多久

宿主会为每个插件登记一条 `runtime_plugin` 贡献，把实例保活到 `shutdown`。  
所以实例方法的 Callable 也不会悬空，技术上能跑。

但**推荐静态 Callable**，原因有三：  
静态注册表比插件实例活得久这件事在别处（例如注册到 Godot 全局信号）不受保护；  
静态函数天然无状态，热重载（插件中心里停→启）不会带出上一次的残留；  
静态函数能被测试直接调用。

## 3. 节点定义

一个 `nodes*.json` 可以放多个节点，文件名随意（`nodes.json` / `nodes_io.json` 都行），  
由插件用 `node_files()` 列出来。**一个节点类型只能由一个插件定义**，重复定义会在启动时报冲突。

### 3.1 顶层

```json
{
	"category": "图像/处理",
	"nodes": [ { ... }, { ... } ]
}
```

`category` 是默认分类，节点里的 `category` 可以覆盖它。  
面板按 `主分类/子分类` 分组显示，`/` 前是标签页、后是分区。

### 3.2 节点字段

| 字段                   | 默认                  | 说明                                      |
| -------------------- | ------------------- | --------------------------------------- |
| `id`                 | —                   | 类型 id，建议 `域.动作`。蓝图 JSON 里存的就是它          |
| `label`              | = id                | 显示名，过语言包                                |
| `desc`               | `""`                | 说明，面板详情与悬停提示用                           |
| `op`                 | = id                | 算子 id，指向 `ops()` 里的键                    |
| `inputs` / `outputs` | `[]`                | 端口数组                                    |
| `params`             | `[]`                | 参数数组（同时也是**可连线的输入端口**）                  |
| `category`           | 顶层                  | 覆盖分类                                    |
| `is_output`          | `false`             | 终点节点，图执行到这里算一帧结束                        |
| `evaluate_always`    | `false`             | 即使没有下游也每帧求值（预览、写盘这类汇点用）                 |
| `gpu`                | `false`             | 必须在主线程求值（GPU 资源、有状态的系统调用）。图里有它，整帧不出工作线程 |
| `cache`              | 有 `exec` 入时 `false` | 允许跨帧复用上一帧结果                             |
| `port_provider`      | `""`                | 端口动态生成器的 id（图层、分支、子图边界这类结构可变的节点用）        |
| `icon`               | `""`                | 节点自己的图，相对插件目录                           |
| `icon_anim`          | `{}`                | `{cols, rows, fps}`，把 `icon` 当精灵表播动画    |

### 3.3 端口

端口表不是只读节点 JSON：`FxCatalog.ports(def, params)` 把它拼成三段的并集 ——
静态端口 → **参数端口**（每个 `bindable` 参数都长成一个入口）→ **动态端口**。
执行器、校验器、编辑器读的都是这一张表，所以「界面看到的」和「执行时认的」不可能对不上。

动态端口由 `port_provider` 指到一个生成器（`FxPortProviders.build()`），
现有实现：`output_layers`（每个图层一个入口）、`sequence`（几段就几个执行出口）、
`subgraph`（按子工程里声明的输入/输出节点长端口）。

想加新的动态端口：在节点定义写一个新的 provider id，然后

```gdscript
# plugins/core.graph/fx_port_providers.gd —— 与图层、序列、子图并列
match id:
    &"my_ports":
        return _my_ports(params, inputs, outputs)

static func _my_ports(params: Dictionary, inputs: Array[Dictionary],
        outputs: Array[Dictionary]) -> Dictionary:
    var ins: Array[Dictionary] = []
    for spec in inputs:
        ins.append(spec.duplicate(true))
    for i in range(int(params.get("count", 1))):
        ins.append({"id": "slot_%d" % i, "label": str(i + 1), "type": FxPortType.IMAGE,
            "required": false, "multi": false, "bindable": false, "param": false})
    return {"inputs": ins, "outputs": outputs}
```

三条注意：

- **不要在 provider 里改传进来的数组**，复制一份再返回（`FxCatalog.ports` 传的是内部数组）；
- provider 会随参数变化被频繁调用，别在里面读盘 —— 要读就自己按 `路径 + 修改时间` 缓存；
- 端口 id 变了等于断线：用「序号」而不是「名字」当 id（图层用 `layer_<id>`，子图用节点 id）。

```json
{"id": "image", "label": "图像", "type": "image", "required": false, "multi": false}
```

| 字段         | 说明                                     |
| ---------- | -------------------------------------- |
| `id`       | 端口 id。**边只存端口 id，不存插槽序号**，所以增删端口不会毁掉存档 |
| `type`     | 见下表                                    |
| `required` | 界面上标红；不强制求值（缺上游时算子拿不到 key）             |
| `multi`    | 允许多条边接同一个入口                            |
| `param`    | 该端口对应一个参数，供特殊节点用                       |

端口类型（`FxPortType.ORDER`，**只能追加不能重排**，int 类型号是旧存档的稳定配色索引）：

| type           | 中文   | 色  |
| -------------- | ---- | -- |
| `any`          | 任意   | 灰  |
| `exec`         | 执行   | 白  |
| `image`        | 图像   | 蓝  |
| `number`       | 数值   | 橙  |
| `int`          | 整数   | 深橙 |
| `bool`         | 布尔   | 红  |
| `string`       | 文本   | 黄  |
| `color`        | 颜色   | 粉  |
| `vec2`         | 向量   | 紫  |
| `layer`        | 图层   | 绿  |
| `image_object` | 图像对象 | 青  |

`image` 与 `image_object` 双向可连，值会自动 wrap / unwrap：  
任何老节点的图像输出都能直接接给读属性的节点。

### 3.4 参数

```json
{"id": "radius", "label": "半径", "kind": "int", "default": 4,
 "min": 1, "max": 32, "step": 1, "unit": "px", "bindable": true}
```

| 字段                     | 说明                                                   |
| ---------------------- | ---------------------------------------------------- |
| `kind`                 | 控件类型，见 [5. 参数控件](#5-参数控件)                            |
| `default`              | 默认值，深拷贝                                              |
| `min` / `max` / `step` | 数值类控件用                                               |
| `unit`                 | 单位后缀，显示在输入框里                                         |
| `options`              | 枚举候选，元素可以是字符串或 `{value, label}`                      |
| `hint`                 | 占位提示 / 悬停说明                                          |
| `multiline`            | `kind: "string"` 时用多行输入框                             |
| `bindable`             | **默认 true**：任何参数都能被上游连线驱动。结构性的参数（图层数组、分支步数）写 `false` |
| `display_fallback`     | 声明式「0 表示跟随」：0 时显示这个表达式的有效值，改到别的值才写盘                  |

`display_fallback` 的例子（最终输出节点的画布宽）：

```json
{"id": "canvas_width", "label": "宽", "kind": "int", "default": 0,
 "min": 0, "max": 4096, "display_fallback": "canvas.width"}
```

显示的是图设置里的宽度，文档里仍存 0；用户改成 800 才变成覆盖值，改回 0 恢复跟随。

### 3.5 视觉：三级回退

添加节点面板给每个节点画一张**缩略图**，取图顺序是：

1. 节点自带 `icon`（有 `icon_anim` 就播动画，`.gif` 自动按单行精灵表切帧）
2. **真实渲染样张**：面板拼一条「棋盘 + 圆盘 → 目标节点」的迷你链跑一帧
3. 分类色块 + 分类字形（按分类字符串哈希出稳定色相）

也就是说：**不画图标也能看**，图像类节点天然有样张；纯数值/流程/导出类会落到第 3 级。  
想让自己插件的节点在这面板里更醒目，就给 `icon`：

```json
{"id": "my.glow", "icon": "assets/icons/glow.png", "icon_anim": {"cols": 4, "rows": 1, "fps": 8}}
```

`icon` 相对**所属插件目录**解析，也可以写 `res://` / `user://` 绝对路径。  
同理，插件自己的图标走 `plugin.json` 的 `icon`。

## 4. 算子与求值上下文

### 4.1 签名

```gdscript
static func apply(ctx: FxEvalContext, node: Dictionary, def: FxNodeDef,
		inputs: Dictionary, params: Dictionary) -> Dictionary
```

- `node`：节点在文档里的字典（`id` / `type` / `params` / `pos`…）。读它来区分同一算子的不同用法
- `def`：`FxNodeDef`，端口与参数定义
- `inputs`：**已求值的上游值**，key 是端口 id；没接线的端口不出现
- `params`：**本帧解析后的参数**，关键帧已采样、被连线驱动的已回填
- 返回：`{端口id: 值}`，写你要输出的端口。没写就等于输出 `null`

### 4.2 ctx 字段

| 字段                          | 说明                                       |
| --------------------------- | ---------------------------------------- |
| `canvas`                    | `Vector2i`，本帧画布尺寸。**图像输出应该用这个尺寸**        |
| `t`                         | 当前时间（秒）                                  |
| `fps` / `duration` / `loop` | 时间轴参数                                    |
| `node_params`               | 每个节点本帧用到的参数表（编辑器显示「被连线驱动」用，别改）           |
| `assets`                    | 素材缓存，跨帧共享                                |
| `state`                     | 本次执行的临时状态                                |
| `operator_quality`          | `[0,1]`，质量策略注入的算子级系数。逐像素算子可以按它降步长        |
| `quality`                   | `0` = 交互预览，`1` = 精确（导出/测试）               |
| `warn(text)`                | 报一条警告。**不要 `push_error`**：一个算子的错误不该刷爆控制台 |

```gdscript
ctx.warn("my.glow：缺少输入图像，输出空画面")
```

### 4.3 取参数

参数值来自 JSON / 连线 / 关键帧插值，类型不一定可靠。统一用 `FxPortType` 收口：

```gdscript
var radius := FxPortType.as_int(params.get("radius", 4), 4)
var amount := FxPortType.as_number(params.get("amount", 0.6), 0.6)
var mode := FxPortType.as_string(params.get("mode", "normal"), "normal")
var color := FxPortType.as_color(params.get("color", "#ffffff"), Color.WHITE)
var offset := FxPortType.as_vec2(params.get("offset", [0, 0]), Vector2.ZERO)
var enabled := FxPortType.as_bool(params.get("enabled", true), true)
```

颜色在文档里存 `#rrggbb` 字符串，关键帧插值时会被解析成 `Color` 再插值，  
所以这两条路你都要能兜住——`as_color` 就是干这个的。

### 4.4 图像约定

- 输出图像尺寸**必须等于 `ctx.canvas`**，除非你有意改变画布（改画布是显式节点的事）
- 格式统一 `RGBA8`，透明画布的初值是 `Color(0,0,0,0)`
- 不要原地改上游传进来的 `Image`：那是别人的缓存，`duplicate()` 之后再动

### 4.5 性能

逐像素 `get_pixel` / `set_pixel` 在 GDScript 里非常慢。用 `core.pixels` 提供的两把工具：

```gdscript
# 生成：fn(x, y, w, h) -> Color
var image := FxPixelKit.generate(ctx.canvas, func(x: float, y: float, w: float, h: float) -> Color:
	return Color(x / w, y / h, 0.5, 1.0))

# 逐像素变换：fn(x, y, c, w, h) -> Color
var tinted := FxPixelKit.map(source, func(_x: float, _y: float, c: Color, _w: float, _h: float) -> Color:
	return Color(c.r * 0.5, c.g, c.b, c.a))

# UV 重映射：fn(x, y, w, h) -> Vector2（返回采样 uv）
var warped := FxPixelKit.remap(source, func(x: float, y: float, w: float, h: float) -> Vector2:
	return Vector2(x / w, y / h + sin(x * 0.1) * 0.02)
```

`FxPixelKit` 直接操作 `PackedByteArray`，比逐点 `Color` 快一个数量级；  
`sample(buf, size, px, py)` 提供双线性采样，自己做卷积时用它。

模糊、缩放这类**能用引擎 C++ 方法**做的，就别自己写循环：

```gdscript
var small := image.duplicate()
small.resize(w / 4, h / 4, Image.INTERPOLATE_BILINEAR)
small.resize(w, h, Image.INTERPOLATE_BILINEAR)
```

混合用 `FxImageUtil.blend_image(dst, src, offset, mode, opacity)`，  
mode 取 `normal / add / multiply / screen / overlay / subtract`。

### 4.6 会读时钟的算子

算子内部用 `ctx.t` 或在上游有轨道时才有不同结果，要把 op id 写进 `time_dependent_ops()`：


```gdscript
func time_dependent_ops() -> Array:
	return [&"my.spin"]
```

执行器据此关闭跨帧缓存。**不声明不会崩，只是它会缓存成静止画面**——
这是最容易被忽略的「我的节点不动的」原因。

## 5. 参数控件

### 5.1 内置 kind

基座自带这些，节点定义里直接写：

`float` / `number` / `int` / `integer` / `vec2` / `bool` / `color` / `enum` / `string` /
`path` / `save` / `dir`

- `string` + `"multiline": true` → 多行输入框
- `path` / `save` / `dir` → 输入框 + 「…」按钮，走原生文件对话框
- 除 `layers` 外，**所有参数都能打关键帧**

### 5.2 自定义 kind

领域控件（字体、贴图、配方、着色器…）由插件自己注册：

```gdscript
func param_kinds() -> Dictionary:
	return {"font": FxFontWidget.build}
```

构建函数契约：

```gdscript
static func build(ctx: Dictionary) -> Dictionary
```

ctx 字段：

| key | 类型 | 说明 |
| --- | --- | --- |
| `param` | Dictionary | 参数元数据（id/label/kind/min/max/options/hint…） |
| `get` | Callable | 取当前显示值（轨道已采样） |
| `set` | Callable | 写值。**必须走它**，它负责可逆与文档更新 |
| `dialog` | Callable | 打开资源选择框，`(kind, on_pick)` |
| `host` | Control | 节点视图，用作对话框父节点 |
| `fallback_get` | Callable | `display_fallback` 的取值器（可能无效） |
| `node_get` | Callable | 取整个节点字典（需要看别的参数时用） |

返回：

```gdscript
{"control": Control, "sync": Callable}
```

`sync` 在时间变化、撤销重做、外部改文档时被调用，负责把控件显示刷成最新值。
**不要在 `build` 里读一次值就完事**——时间是会动的，撤销是会来的。

已注册的领域控件：`font`（core.text）、`texture` / `pixelfx`（core.asset）、
`recipe`（core.recipe）、`shader`（core.shader）、`graph`（core.graph，选工程文件）。

写自定义控件的两个细节：

- 自定义控件**不继承皮肤 Theme**，要订阅 `FxShell.skin_changed` 后 `queue_redraw()`
- 弹窗等 `tree_entered` 再弹：`FxUiKit.popup_later(dialog, "popup_centered_ratio", [0.6])`，
  直接 `popup_centered()` 会撞 `_sub_window_grab_focus: index == -1`

### 6.1 面板

```gdscript
func panels() -> Array[Dictionary]:
	return [{
		"id": "panel.my.inspector",
		"title": "检视器",
		"area": "right",          # center | left | right | bottom
		"order": 50,
```

```gdscript
static func build(ctx: Dictionary) -> Control:

	return panel
```

## 8. 服务、能力与设置

### 8.1 inject / provide 是什么

```json
"inject": ["kernel.graph", "plugin.core.pixels"],
"provide": {"plugin.my.glow": "1.0"}
```

- **`inject` 是依赖声明**，不是「拿到对象」。它决定加载顺序：你 inject 的键必须已经有人 provide
- **`provide` 是承诺**：我这个插件加载完，这些键就存在了
- 启动时会检查：注入了没人提供的键 → 记一条错误、插件保持未激活；两个人 provide 同一个键 → 冲突错误
- 环依赖会被静态检出并报出来

那怎么真正使用别人的能力？两条路：

1. **静态门面**（绝大多数情况）：`FxGraphFacade` / `FxRenderBroker` / `FxNodePickerBroker` /
   `FxDropBroker` / `FxPanelBroker` / `FxI18n` / `FxSettings` / `FxCapabilities` /
   `FxQualityPolicy` / `FxResourceRoot`。这些是基座键的代理，插件在不在都能调（有安全降级）
2. **领域静态类**：`FxCatalog` / `FxImageUtil` / `FxPixelKit` / `FxPortType` 这些不贡献、只提供函数的类，
   直接调即可；它们来自哪个插件由 `inject` 声明顺序保证已加载

基座自己提供的键（可以直接 `inject`）：
`core.shell` / `core.catalog` / `core.document` / `core.render` / `core.registry` /
`core.plugins` / `graph.facade` / `renderer.broker` / `node_picker.broker`。

### 8.2 自定义服务

```gdscript
func services() -> Dictionary:
	return {"my.service": FxMyService.create}
```

工厂收到 ctx：`{shell, store, render, services, plugin_id}`，返回值可以是 Node、
RefCounted 或纯数据。别人用 `inject` 声明依赖后，通过 `FxShell.service(id)` 取。

### 8.3 设置项

```gdscript
func settings() -> Array[Dictionary]:
	return [{
		"id": "my.strength",
		"label": "默认强度",
		"group": "插件",
		"kind": "float",
		"default": 0.6,
		"min": 0.0,
		"max": 1.0,
		"step": 0.01,
		"description": "新建节点时的初始强度",
		"applies": "runtime",       # runtime | ui | none
		"capability": "my.apply",   # 变化时 dispatch 给哪个能力键
		"order": 100,
	}]
```

基座不解释语义：它只负责**声明式持久化 + 按字段协调**。读值用
`FxSettings.typed_value("my.strength", 0.6)`，订阅用 `FxSettings.subscribe(cb)`。

**按钮型条目**（`kind: "action"`）没有值、不写 `settings.cfg`，点一下执行 `action`：

```gdscript
{"id": "my.clear", "label": "缓存", "kind": "action", "button": "清理缓存",
 "action": FxMyApi.clear_cache, "applies": "none", "order": 110}
```

`action` 必须是**零参数**的 Callable（静态函数，或 `some_callable.bind(args)`）。
设置面板渲染成 `FxUiKit` 按钮；回调里要提示用户就用 `ctx` 自己拿 `shell.status()`。
`render.cache_clear` 就是这么做的。

### 8.4 能力代理

```gdscript
func capabilities() -> Array[Dictionary]:
	return [{"key": "my.apply", "apply": FxMyApi.apply_strength, "order": 10}]
```

同一个键允许多个 provider 共存，按 `order` 依次 `apply(value)`。
`FxCapabilities.dispatch(key, value)` 广播，`FxCapabilities.providers(key)` 查现状。

### 8.5 质量策略

```gdscript
func quality_policies() -> Array[Dictionary]:
	return [{
		"order": 10,
		"apply": func(ctx: Dictionary, current: Dictionary) -> Dictionary:
			return {"operator_quality": 0.5},   # 只返回要覆盖的字段
	}]
```

输出链永不降采样这条不变量由基座守住，策略只能动算子级系数。

## 10. 多语言

**谁注册的文案谁翻译。** 基座只翻译外壳自己的字（菜单、停靠标签、状态栏），
`core.i18n` 永远不去读别人的插件目录。

插件译文放 `plugins/<id>/locales/<locale>.json`，文件名就是语言代码：

```json
{
	"name": "English (US)",
	"entries": {
		"文字": "Text",
		"用外部字体渲染文字，支持描边与对齐": "Renders text with external fonts, outlines and alignment"
	}
}
```

宿主加载时自动登记，全局按 `order` 合并成一条回退链（当前语言 → 基础语言 → 原文）。

也可以用代码贡献（动态生成译文时）：

```gdscript
func locales() -> Array[Dictionary]:
	return [{"locale": "en_US", "name": "English (US)", "order": 50,
		"entries": {"辉光": "Glow"}}]
```

规则：

- **键名必须全局唯一**。多个插件用同一个键会互相覆盖，写成「原文」最容易撞，
  可以带前缀：`"my.glow.半径": "Radius"`
- 节点名、面板标题、设置项、命令、皮肤名、参数标签、枚举候选项都会过语言包——你只要提供译文
- 切语言即时生效：`FxI18n.text(key)` 的订阅者会收到通知

## 11. 素材与资源根

插件自带的图片/字体/着色器放 `plugins/<id>/assets/`，并**在该目录放一个 `.gdignore`**：

```
plugins/my.glow/assets/.gdignore
```

`.gdignore` 让 Godot 不导入它们（不进 PCK，不生成 `.import`），
素材跟着插件目录一起分发。读取时不要写死 `res://`，用资源根解析：

```gdscript
var path := FxResourceRoot.resolve("plugins/my.glow/assets/icon.png")
```

解析顺序：`res://` → `<exe 同级>/` → `user://` → 注册的额外根。
`FxPlugin.local("assets/icon.png")` 只是拼出 `res://plugins/my.glow/assets/icon.png`，
真正落到外部文件还得过 `FxResourceRoot`。

## 12. 替换核心

这三条是「一切皆插件」的极限用法：**换掉执行器、换掉渲染器、换掉添加节点面板**。

### 12.1 图能力（graph_access）

```gdscript
func graph_access() -> Array[Dictionary]:
	return [{"id": "my.evaluator", "label": "我的执行器", "order": 100,
		"factory": FxMyGraphAccess.new}]
```

实现 `FxGraphAccess` 接口，就换掉了整个图解释器。
蓝图层只依赖 `FxGraphFacade` 代理，所以停用你的插件会自动回落到内建实现。

接口里有两个「跟编辑器分工」的方法，实现新的解释器时别漏：

| 方法 | 谁在用 | 约定 |
|---|---|---|
| `doc_resolve_path(raw) -> String` | 双击下钻子图 | 把参数里的路径解析成真实可读路径；找不到返回空串 |
| `catalog_openable(type) -> bool` | 双击是否下钻、菜单项是否置灰 | 「这个节点内部还有一份文档」时为 true |

内建实现的判据是 `def.port_provider == "subgraph"`（不是类型 id），
所以以后多一个「把文档当节点」的类型，挂上同名 provider 就自动获得双击下钻。

**文档写入也归你**：`FxDocumentStore` 只做撤销栈、coeffect 通知与批量合成，
方法名保持不变，但真正的图语义都转给 `FxGraphFacade.access()`。换图解释器时，
下面这组方法要一起实现（默认空实现是「安全不动」，不会崩但也不会有效果）：

| 方法 | 用途 |
| --- | --- |
| `doc_normalize(doc)` | 装载一份外部文档时规整成合法结构 |
| `doc_node(doc, id)` | 取节点数据（撤销/选中/参数读写都靠它） |
| `doc_add_node` / `doc_remove_node` / `doc_connect` / `doc_disconnect` / `doc_set_output` | 结构与连线变更；`doc_add_node` 还负责「第一个输出节点自动成为最终输出」 |
| `doc_apply_path(doc, node_id, path, value)` | 嵌套轨道路径（如 `layers.0.opacity`）的数组展开 |
| `doc_set_timeline` / `set_doc_canvas` / `doc_set_node_pos` | 时间轴、画布、节点坐标 |
| `catalog_ensure` / `catalog_refresh` / `catalog_all` | 首次扫描与插件启停后的目录重建 |
| `link_ok` / `link_no_node` / `link_type` / `link_cycle` | 连线错误码（失败的效果不能留撤销点） |

`FxVisualIcon`（节点分类字形、图标路径、精灵表动图）也住在 `core.graph`：
它不是基座服务，写自定义目录时记得一并带上分类映射。

### 12.0b 时空可组合：两个新的贡献点

按「空间 / 时间正交可组合」的分工，基座只保留组合规则，语义全由插件贡献。
写新插件时优先用下面两个贡献点，别把领域字段塞回基座 UI：

**`status_fragment()`** —— 状态栏领域片段：

```gdscript
func status_fragments() -> Array[Dictionary]:
    return [{
        "id": "my.status", "order": 20,
        "handler": FxMyApi.status_fragment,     # 静态 (stats: Dictionary) -> Dictionary
        "diagnostic": FxMyApi.diagnostic_line,  # 可选，启动时 (service) -> String
    }]
```

`handler` 返回 `{text: String, tone: String}`，`tone` 只允许
`"" / "ok" / "accent" / "danger"` 三种通用语气（基座映射到皮肤色）。
基座只渲染「节点 / 步数 / ms / ⚠」并拼接片段，**不认识任何插件专有字段**。
`diagnostic` 用来在 `--fx-diagnose` 里打印自己的运行配置，别让外壳 `get()` 你的内部对象。

**`clocks()`** —— 时间维度：

```gdscript
func clocks() -> Array[Dictionary]:
    return [{"id": "my.clock", "priority": 10, "factory": FxMyClock.create}]
```

`factory` 必须返回满足契约的对象：`reset(at_frame)`、`advance(delta, fps, count) -> bool`、
`time_of(index, fps)`、`frame_at(t, fps, count)`、`frame` 属性。
`FxClockBroker.create()` 按 priority 选一个；不合规的实现会被跳过。
`core.timeline` 的 `FxPlaybackClock` 是参考实现（一次 advance 至多跨一个帧号），
`core.render` 的 `FxLinearClock` 只是「插件被停用」时的降级，不要直接依赖它。

**主线程泵**：`FxRenderGate.set_main_thread_pump(cb)` 注册每帧一次的回调，
基座用 `pump_main_thread()` 调用。旧的 `set_gpu_pump / pump_gpu` 是兼容别名，
新代码不要用 —— 组合规则不该以设备类型命名。

### 12.1a 像素算子的性能契约（批量循环）

`FxPixelKit.generate / map / remap` 每像素调一次 `Callable.call()`：192×108 单张图
光调用开销 ~10 ms（微基准 14.8 → 3.7 ms，去掉 call 后 **4×**）。写新算子请用批量 API：

| API | Callable 签名 | 说明 |
| --- | --- | --- |
| `generate_batch(size, fn)` | `fn(w:int, h:int) -> PackedByteArray` | 自己 `resize(w*h*4)` 并填 RGBA8 |
| `map_batch(source, fn)` | `fn(src:PackedByteArray, w:int, h:int) -> PackedByteArray` | 读 src 写 dst，长度一致 |
| `remap_batch(source, fn)` | `fn(w:int, h:int) -> PackedFloat32Array` | 每像素两个 float（源像素 u,v），双线性采样在套件内内联 |

要点：

- **循环必须写在 lambda 里**，整图只调用一次；常量（角度、颜色、模式 id、倒数、
  三角函数表）提到循环外，循环内不要 `match "字符串"`。
- 写字节用 `int(clampf(c.r * 255.0 + 0.5, 0.0, 255.0))`，与原
  `round(clampf(c.r,0,1)*255)` 对 0..1 全 256 级逐字节一致；`FxPixelKit.pack()`
  是等价的便捷函数，但热点循环里展开更快。
- 旧 API 全部保留，第三方插件不受影响；内建热点算子已迁移。
- 同理避免 `Image.get_pixel/set_pixel`：一次 `get_data()` 拿字节缓冲再搬运，
  `transform` 从 68 ms 降到退出前四大开销。

**图结构索引**：`FxGraphRunner._build_index()` 按 `hash(nodes)+hash(edges)`
跨帧复用（103 节点 0.034 ms），文档不变就只清端口表。自定义 op 不要直接改
`doc.nodes/edges` 而不触发修订号，否则索引会拿不到新结构。

### 12.2 渲染后端（render_backends）

```gdscript
func render_backends() -> Array[Dictionary]:
	return [{"id": "my.renderer", "label": "我的渲染器", "order": 100,
		"factory": FxMyBackend.new}]
```

实现 `FxRenderBackend`。后端要声明 `thread_safe()`：
返回 `true` 才能被工作线程调用（见 README 的「后台求帧」）。
另有 `postprocess(image, ctx) -> Image` 钩子：服务在**发布前的主线程**调用一次，
给「只能渲染线程碰」的资源（RenderingDevice compute / 纹理）留通道。
播放命中的缓存帧也会过一遍，所以缓存里存的始终是 CPU 原始帧（与导出一致），
增强只影响显示；实现方必须同步、失败就返回输入图。

**别把整条求值链钉在主线程上**：`RenderingDevice.compute_list_begin` 与
`SubViewport.get_texture().get_image()` 都只允许渲染线程调用（试过
`create_local_rendering_device()` 也一样）。正确做法是
① `thread_safe() = true` 让求值留在工作线程；
② 需要 GPU 的算子把请求排进队列，由插件在 `activate()` 里
`FxRenderGate.set_gpu_pump(自己的 pump)` 注册一个每帧回调，
渲染服务每个 process 调 `FxRenderGate.pump_gpu()` 处理一小批并回写结果，
工作线程只等自己那条（要带超时，停用时 `close_bridge()` 唤醒所有等待者）。
`core.shader` 的 `FxShaderRuntime.render_bridged()` 就是这条路的参考实现。

`render.gpu` 是逐算子 GPU 化的参考实现：`thread_safe() = true`（GPU 只在 postprocess 里碰），
`FxGpuCompute` 用 `RenderingDevice` 的 compute shader 读写 RGBA8 缓冲
（`buffer_get_data()` 是同步栅栏，像素原样进出），`FxGpuOps` 以**同名 op 覆盖**
`image.blur` / `image.mix`，不满足「GPU 后端 + 设备可用 + 主线程」就委托回 `FxOpsImage`。
无设备/无头时 `FxGpuDevice.available()` 为假，后端自己退化，不需要基座兜底。

**GPU 算子在工作线程里也能用**：`RenderingDevice.compute_list_begin` 只允许渲染线程，
但 `RenderingServer.call_on_render_thread(cb)` 可以让工作线程提交 compute。
`FxGpuCompute.bridged()` 内部是**领导线程 + 批**：先入队者发起一次回调，
回调抽干整个队列（含等待期间新进的请求）后统一回写，队列空时放开领导权。
实测 6 线程各 8 个请求 → **1~2 批**、0.8–2.1 ms/请求（旧实现每请求一次往返 16 ms）。
主线程 / 渲染线程直接执行不排队。用
`FxGpuCompute.bridged({"kind": "my_op", ...})`（主线程/渲染线程直接执行，
工作线程提交一次回调等结果，2 s 超时返回 `null`），**不要**自己调 `submit()/sync()`。
`FxGpuOps.active()` 只查设备与 `render.gpu_ops` 开关，不要求选了 GPU 后端，
也不要求主线程：GPU 是逐算子加速。无设备、编译失败、桥超时一律委托回原 CPU 算子。
`render.backend` 的默认值是**空**（= 自动）：`FxRenderBroker.current_id()` 取贡献
`order` 最小的后端（当前 `render.gpu` 声明 order=5，所以默认走 GPU）。基座不硬编码
任何插件 id；插件缺失时 `instance()` 回落到第一个可用后端，逐像素算子另有
`render.gpu_ops` 闸门，无显卡机器不会黑屏。
`_probe_gpu_worker.gd` 是「CPU 逐字节对齐 + 工作线程桥」的参考探针。

要加一个 GPU 算子：① 在 `COMPUTE_CODE` 里加一个 `op` 分支，用 `cfg` 传参；
② 在 `FxGpuOps` 写同名静态函数，先 `active()` 判断，再 `FxGpuCompute.run(...)`，
返回 `null` 就回落原实现；③ 在 `plugin.gd` 的 `ops()` 注册，并在 `plugin.json`
的 `inject` 里声明提供原算子的插件 key（例如 `plugin.core.image`）——
**依赖顺序决定同名 op 谁覆盖谁**，不声明的话加载顺序可能反过来。

`core.render` 还贡献了逐帧缓存（`FxFrameCache` / `FxFramePrefetcher`）与服务 API：

| 方法 | 用途 |
| --- | --- |
| `cache_state(index)` / `frame_count()` / `frame_index()` | 时间轴标尺给每帧画红 / 黄 / 绿色块 |
| `cache_stats()` / `prefetch_progress()` / 信号 `cache_changed` | 状态栏显示「缓存 x/y · 预渲染 n/y」 |
| `start_prefetch(manual)` / `cancel_prefetch()` / `clear_cache()` | 手动调度与清理（设置里的按钮走 `FxRenderApi.clear_cache`） |

自定义后端只要 `frame()` 返回 `{image, stats, previews}`，缓存与预渲染自动生效。
预渲染不再依赖当前后端的 `thread_safe()`：它算的是 CPU 原始帧，GPU 增强由
主线程发布通道负责，因此切到 GPU 后端同样会并行补缓存。
`FxFramePrefetcher` 现在按核数开 2~6 条线程，自定义后端若持有可变全局状态，
必须自己做互斥（推荐像内置执行器那样每线程一个实例）。

**帧缓存是紧密单文件**：每个桶一个 `frames.fxc`（64 字节头 + 每帧 1 字节位图 +
定长 RGBA8 像素），`fetch(i)` = `seek(64 + N + i*w*h*4)` 后一次 `get_buffer`，
零 PNG 编码。位置由 `render.cache_location` 决定（`exe` 默认落在软件本体目录、
`user` 用户目录、`memory` 纯内存），`render.cache_max_mb` 做 LRU 自动清理，
`render.cache_memory_mb` 控制内存热层。自己实现缓存后端时，务必保证
`put/fetch/state/stats/clear/clear_all` 这套接口不变，并自己处理多线程写互斥。

**结果世代契约**（写自定义后端/求帧任务时必读）：每个 job 提交时带
`epoch`（播放世代）与 `doc_key`（`FxDocumentStore.content_key()`），
结果原样回传。`FxRenderService._publish()` 任一不匹配就**整个丢弃**，
连缓存都不写 —— 过期结果属于另一份文档或另一个播放状态，归档回去只会
把正确帧覆盖成旧数据。`content_key = 世代 × 2²⁰ + 修订号`：
`attach()` 会把 `revision()` 归零，所以不能只用修订号当文档身份。
停止播放时若当前帧已精确缓存，服务直接定格，不再发一次低质量重算盖掉它。
`FxFrameCache.put/fetch` 还会校验帧尺寸与文档画布一致，异形帧直接拒绝
（紧密文件是定长偏移布局，混进一张不同尺寸的图会整桶错位）。

**播放中的缩略图**：缓存里只有整帧结果，没有逐节点中间图。编辑器用
`FxRenderService.set_preview_focus(ids)` 报上「当前展开的节点」，预渲染在算帧时
只捕获这些节点（`preview_nodes`，`preview_limit = 72`），存进 `FxPreviewTrack`；
播放到第 i 帧时发 `frame_previews(index, previews)`，面板只推给未收起的视图。
收起的节点**连求值都不做** —— 自定义面板如果也有「按帧刷新的小图」需求，
订阅这个信号而不是自己每帧求值。

**布局不算数据**：`commit_batch(["positions"])` 只改节点位置，服务会整条忽略
（不置脏、不换桶、不重画）；`FxFrameCache.fingerprint_of()` 也只对影响像素的字段
取哈希（剔除节点 `pos`/`size` 与连线折点）。自定义面板做「拖动整理」这类纯布局操作时，
请用 `positions` 键提交，别塞 `structure`，否则每次拖拽都会让整段缓存作废。

**播放契约**：`FxRenderService` 播放时只读 `FxFrameCache.fetch()`，
不在界面线程求值；帧号每个 process 至多 +1，绝不跳号。时间推进走
`FxDocumentStore.set_time_silent()`（只发 `time_ticked`），
因为 `set_time()` 的 `notify()` 会广播给所有 coeffect fiber ——
103 节点工程实测每帧 131 ms。自定义面板要跟随播放头就订阅 `store.time_ticked`，
不要依赖 `store.changed(["time"])`。
要换的只是「求一帧」这一步，UI、导出、快捷键全部照旧。

### 12.3 节点选择器（node_pickers）

## 13. 原生算子（GDExtension）

C++ 实现的算子和脚本算子在宿主眼里是同一个东西：**一张 op 表**。
节点定义只写 `"op": "my.blur"`，实现是 C++ 还是 GDScript 对蓝图完全透明。

```json
{"native": {"library": "native/fx_blur.gdextension"}}
```

```gdscript
func native_ops() -> Array[Dictionary]:
	return [{"op": "my.blur", "class": "FxBlurOp", "thread_safe": true}]
```

C++ 类要按窄 ABI 暴露 `fx_exec(inputs, params, env) -> Dictionary`。
`thread_safe: false` 时，图里有这个节点就整帧回主线程求值（C++ 侧有可变状态时必须声明）。

## 14. 硬性规则

这十条踩了会出真问题，不是风格问题。

1. **算子/导出器/面板工厂用静态 Callable。** 宿主也接受实例 Callable（实例被
   `runtime_plugin` 保活到停用），但静态写法在热重载、退出、被注册到全局信号时更安全，
   也更容易被测试直接调用。
2. **不要写 `if type == "xxx"`。** 节点类型只存在于 JSON 与 op 表里。
   UI、执行器、导出器都不许认识具体类型。
3. **边只存端口 id。** 增删端口不能靠改序号，「第 2 个输入」这种话在代码里不成立。
4. **不要原地改上游 Image。** 那是别人的缓存，`duplicate()`。
5. **输出尺寸 = `ctx.canvas`。** 例外是显式改画布的节点。
6. **报错用 `ctx.warn()`。** 一个算子的失败不该中断整帧，也不该刷满控制台。
7. **有错就返回空画面，不要返回 `null`。** 下游会拿不到 key 而报更多错。
8. **语言包键名全局唯一。** 撞了会静默覆盖别人的译文。
9. **素材放 `assets/` 并带 `.gdignore`。** 混进 PCK 会让「用户改素材」失效。
10. **不用 `String(int)`、不定义名叫 `ease` / `remap` 的静态函数。**
    `String(int)` 在运行时非法（用 `str()`）；后两个是 GDScript 内建，会撞。

## 15. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 节点加载了但节点面板里没有 | `node_files()` 路径写错，或换成相对路径没走 `local()` | 用 `local("nodes.json")`；启动日志会打印节点数 |
| 我的节点画面不动 | op 读了 `ctx.t` 但没进 `time_dependent_ops()` | 声明它 |
| 求值偶发报「正在被另一个线程使用」 | 算子有可变状态 / 碰了 GPU，却声明成了线程安全 | `gpu: true` 或 `thread_safe: false` |
| 参数改了画面不变 | 用了 `param["default"]` 而不是 `params.get(...)`；或读了 `node["params"]` | 一律读 `params`（已采样、已回填） |
| 参数行显示的值不对 | 上游连线驱动时文档里存的是旧值 | 编辑器读 `ctx.node_params`，你不用管；只要保证算子读 `params` |
| 面板工厂 `push_warning("没有返回 Control")` | 返回了 Node / 数组 | 必须返回 `Control` |
| 弹窗时报 `_sub_window_grab_focus: index == -1` | 对**已显示**的窗口调了 `hide()` | 关窗口只销毁：`FxUiKit.dismiss(w)`；打开用 `FxUiKit.popup_later()` |
| 无头跑测试时剪贴板相关逻辑异常 | 无头环境没有系统剪贴板 | 走内部副本回落，别断言 `DisplayServer.has_feature` 为真 |
| 新增 `class_name` 后无头运行报 "not declared" | 全局类缓存没重建 | 跑一次 `--headless --editor --quit` |
| 面板「拖不小」/ 越拖越宽 | `ScrollContainer` 的横向滚动设成 `DISABLED`，把内部 `GridContainer` 的最小宽度传给了父级，列数反过来钉死宽度 | 改成 `SCROLL_MODE_AUTO`，列数按面板宽度算 |
| `PanelContainer.size` 设了却被撑大 | Godot 的尺寸是 `max(设定值, 内容最小尺寸)`，`custom_minimum_size` 只是下限 | 先压缩内容（改列数/关掉 autowrap），再设尺寸；一帧内做不到就等布局后补一次 |
| 插件被禁用后节点还在 | 节点定义被另一份 JSON 重复声明 | 一个类型只能一个插件定义 |
| 打开工程总弹「缺一堆素材」 | 把 `save` / `dir` 这类**输出目标**也算成输入依赖；导出文件本来就不存在 | 依赖扫描按参数 `kind` 跳过写目标；只缺素材时也不弹窗，状态栏提示 + 手动命令 |
| 自定义设置项需要一个「按钮」 | `kind` 只有 bool/int/float/enum/color/string | 用 `kind: "action"` + `button` + 零参数 `action` |
| GPU 后端切过去黑屏 | 无头/dummy 驱动下建纹理拿到空图 | 设备探测先判 `available()`；读回失败时退回 CPU 结果 |
| GPU 算子输出到上一帧的画面 | `SubViewport.get_texture().get_image()` 有帧延迟，`force_draw()` 只提交不等待 | 改用 `RenderingDevice` compute + `buffer_get_data()` 同步读回 |
| `Only local devices can submit and sync` | 引擎主 `RenderingDevice` 不是 local device | 不要调 `submit()` / `sync()`；`buffer_get_data()` 自带栅栏 |
| GPU 锐化「看起来没生效」 | 纯黑白样本被 clamp 回原值，或探针只数「变化像素数」把黑图误判为成功 | 用中间调样本，并核对 identity 与 CPU 公式 |
| 播放时 UI 每帧卡 100ms+ | 播放头推进走了 `store.set_time()` 全量 coeffect 广播 | 用 `set_time_silent()` + 订阅 `time_ticked`；交互仍用 `set_time()` |
| 空闲等很久才开始预渲染 | 用 `_dirty` 判空闲，且每次时间变化都把计时归零 | 判 `_cache_dirty`（指纹就绪）+ 0.18s 防抖；`doc` 通知当帧就排上 |
| 播放仍然跳帧 | 按真实时间一次跨多帧，或渲染慢时自适应节流把后续帧全挡掉 | 播放帧号每 process 至多 +1；播放只读缓存，节流只约束交互重算 |
| 预渲染帧少了一层 GPU 效果 | 工作线程碰不到 SubViewport，算子悄悄回退成「原样输出」 | 走 `FxRenderGate` 的主线程 GPU 泵，别让整帧回主线程 |
| 测试里 lambda 计数永远是 0 | GDScript 对 int 是**值捕获**，`count += 1` 改的是副本 | 把计数放进 `Array`/`Dictionary` 容器 |
| 播放发布时报错 `Vector2 != Array` | 实时参数比较没判类型，GDScript 跨类型 `!=` 直接抛错 | `typeof(a) != typeof(b)` 先短路，同类型再比较 |
| 自定义像素算子慢得离谱 | 每像素 `Callable.call()` / `get_pixel+set_pixel` | 用 `FxPixelKit.*_batch`，循环写在 lambda 内、常量外提 |
| GPU 算子在工作线程里报错 | 直接调 `compute_list_begin`（只能渲染线程） | 走 `FxGpuCompute.bridged()`；主线程也别自己 `submit()/sync()` |
| 缓存目录出现在引擎安装目录 | 开发时用 `OS.get_executable_path()` 拿到的是 godot.exe | 检测工具名/编辑器提示并回退 `user://`；exe 不可写也回退 |
| 紧密文件读到上一帧/黑帧 | 忘了写位图，或帧偏移算错（头 64 + N 位图字节） | `_frame_offset(N, bytes, i) = 64 + N + i*bytes`，写完帧再置位图 |
| 播放时节点卡片仍在闪 | 每帧推 100+ 组 live 参数与缩略图 | 播放期冻结、连续求帧按 220 ms 合并，停下补推最新一帧 |
| 预渲染线程报「检测到循环依赖」但图里没环 | 子图执行器/递归栈是静态单例，多线程互相覆盖 `evaluating` | 组合状态放 `FxEvalContext`，跨求值共享的只读缓存才用 `static` + Mutex |
| 打开工程后预览被 128×128 空图覆盖 | `attach()` 把 `revision` 归零，求帧快照没失效 | 用 `content_key()` 做快照键与结果标签，job 回传校验 |
| 停播放后画面回退到旧帧 | 在途旧 job 结果仍被发布；或暂停态又发一次低质量重算 | 结果世代校验 + 命中缓存就定格不重算 |
| 打开工程后帧数还是上一份文档的 | 「桶空着才建桶」的写法：装载前桶里是示例文档的 30 帧，于是跳过重建 | 装载只置 `_cache_dirty`，等稳定期结束后的巡检统一 `prepare()` |
| 缩放/点选节点也把整段缓存作废了 | 修订号只有一个，位置/尺寸写回也让它 +1 | 拆内容修订号与布局修订号，`content_key()` 只跟内容走 |
| 改参数后第一帧显示的是旧图 | 显示缓存只用帧号做键，帧号没变但内容变了 | 键改成「内容身份 + 帧号」 |
| 装载工程时画面闪一下、缓存从头再来 | 装载瞬间就定桶，随后参数面板回写让指纹再变一次 | 换文档后 `CONTENT_SETTLE`（0.35 s）内不定桶、不归档 |
| 节点卡片的角标一直黄/一直灰 | 用「预渲染在跑」猜状态，或拿不到「这一帧已推出」的事实 | 服务侧 `bake_info()` 返回 `{state, frame, shown}`，只按事实判定 |
| 重建视图后报 `previously freed` | `node_views` 里残留已 free 的引用，`!= null` 挡不住 | 统一用 `is_instance_valid()` 判存活 |
| 紧密缓存读到错位像素 | 不同尺寸的帧写进定长桶 | `prepare()` 传入文档画布尺寸，`put/fetch` 校验 |
| 插件贡献的状态栏文案不显示 | 忘了在 `status_fragments()` 里用**静态** Callable | 宿主会拒绝非静态回调，检查 `plugin_info.error` |
| 拖一次节点预渲染就从头再来 | 位置写回用了 `structure` 键，或缓存指纹含 `pos` | 纯布局用 `commit_batch(["positions"])`；指纹走 `content_of()` |
| 工作线程 GPU 请求慢得离谱 | 每个请求各自 `call_on_render_thread` 等一次往返 | 用 `FxGpuCompute.bridged()`（内部批量合流），别再自己包一层 |
| 播放时小图不动 | 面板没订阅 `frame_previews`，或节点是收起状态 | 展开节点会由服务随帧推送；收起节点按设计不产生预览 |

| 缓存色块一直是红 | 文档指纹每次都变（预览帧也写进 doc），或预渲染每次被文档改动取消 | 预渲染只在空闲时排程；指纹变化就取消旧任务，别让旧帧写进新桶 |

## 16. 调试与自检

**启动日志**：`user://logs/startup.log`（不可写时回落 `<exe>/logs/`）。
每个插件的加载、每条错误的原文都在里面，控制台同时也打一份。

**装配诊断**：

```bash
godot --headless --path . -- --fx-diagnose
```

打印插件数 / 节点数 / 参数控件 / 面板 / 设置 / 语言包 / 依赖缺失与环。
写插件时先跑它，比在界面上翻找快。

**依赖报告**（代码里）：

```gdscript
var report := FxPluginHost.dependency_report()
# {missing: [{plugin, key}], inactive: [...], cycles: [...], active: [...]}
```

**写测试**：`tests/` 下每个套件都是一个 `SceneTree` 脚本，`--headless --script` 直接跑。
最小骨架：

```gdscript
extends SceneTree

var failures: Array[String] = []

func _initialize() -> void:
	FxPluginHost.ensure()
	FxCatalog.ensure_loaded()
	_check(FxCatalog.def("my.glow") != null, "节点已注册")
	FxPluginHost.shutdown()   # 无头脚本退出前必须调
	quit(0 if failures.is_empty() else 1)

func _check(condition: bool, label: String) -> void:
	if condition:
		print("  ok  ", label)
	else:
		failures.append(label)
		print("  FAIL ", label)
```

算子本身是纯函数，可以直接喂一个 `FxEvalContext` 调用，不需要场景树：

```gdscript
var ctx := FxEvalContext.new()
ctx.canvas = Vector2i(32, 32)
var out := FxMyGlowOps.apply(ctx, {}, null, {"image": FxImageUtil.new_canvas(ctx.canvas)},
	{"radius": 4, "amount": 0.8})
_check(out.get("image") is Image, "输出图像")
```

```gdscript
# ops_thing.gd
class_name FxThingOps
extends RefCounted

static func apply(ctx: FxEvalContext, _node: Dictionary, _def: FxNodeDef,
		inputs: Dictionary, params: Dictionary) -> Dictionary:
	var source: Variant = inputs.get("image")
	var base: Image = source if source is Image else FxImageUtil.new_canvas(ctx.canvas)
	var amount := clampf(FxPortType.as_number(params.get("amount", 0.5), 0.5), 0.0, 1.0)
	ctx.warn("my.thing 还没实现，先原样透传")
	var out := base.duplicate()
	FxImageUtil.blend_image(out, base, Vector2.ZERO, "normal", amount)
	return {"image": out}
```
