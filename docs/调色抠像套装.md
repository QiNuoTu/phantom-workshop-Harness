# 调色抠像套装（fx.keying / fx.channels / fx.masks / fx.tone / fx.stylize + fx.native-kit）

> 五个**节点插件** + 一个**原生包**，共 29 个算子，把「AE 里美工最常用的那几板」补齐。
> 拆成五个插件的理由和整个项目一致：**一个插件停用后，其余四个照常工作**；
> 谁出问题、谁的版本该涨，都能单独说清。
>
> **28 个算子的唯一实现是 C++**（`fx.native-kit`）。GDScript 版已整条删除 ——
> 见 §5「为什么不留第二条路」。

## 1. 六个目录，各自负责什么

| 插件 | 版本 | 负责 | 明确不负责 |
| --- | --- | --- | --- |
| `fx.keying` | 0.2.0 | 节点定义 + 键色控件 + 抠像台面板 | 不做像素运算（算子全在原生包） |
| `fx.channels` | 0.2.0 | 节点定义 | 通道搬运的**算法**在原生包 |
| `fx.masks` | 0.2.0 | 节点定义 | 蒙版生成/组合的算法在原生包 |
| `fx.tone` | 0.3.0 | 节点定义 + **曲线控件** | 色调算法的在原生包 |
| `fx.stylize` | 0.2.0 | 节点定义 | 风格化算法在原生包 |
| `fx.native-kit` | 0.2.0 | **29 个算子的 C++ 实现**（5 个族类）+ 自带 DLL | 不贡献节点、不做 UI |

依赖方向只有一条：五个节点插件 `inject: ["plugin.fx.native-kit"]`。
原生包缺席 → 五个插件不激活 → 它们的节点一起消失。**这是设计好的边界，不是意外**：
缺一样东西时"这个功能不在"比"这个功能慢十倍"诚实。

与已有插件的关系（都有交集，但语义不同，**不覆盖**）：

| 已有 | 与谁相邻 | 为什么保留两份 |
| --- | --- | --- |
| `fx.color/image.chroma_key` | `fx.keying/key.chroma_pro` | 前者是单色距 + 容差的简版，工程里已经用着；换掉会静默改掉老工程的结果 |
| `fx.color/image.posterize` | `fx.tone/tone.posterize_pro` | 前者 RGB 三通道各自分档；后者多了「按亮度分档」与台阶平滑 |
| `fx.composite/image.mask` | `fx.masks` 的一整族 | 前者是"用另一张图当遮罩"，后者是**从零造**蒙版、做布尔、做羽化 |

## 2. 节点清单（28 个）

### fx.keying（抠像，6）

| 节点 | 一句话 | 关键参数 |
| --- | --- | --- |
| 专业绿幕抠像 | 按**色度**距离出 alpha（对绿布上的阴影不敏感） | 屏幕色 / 黑点 / 白点 / 色相权重 / 收缩 / 柔化 / 去溢色 / 边缘去色 / 显示 |
| 亮度键 | 按亮度或某条通道抠：黑底、白底、扫描稿 | 取哪条 / 黑点 / 白点 / 反相 |
| 差值键 | 和一张干净背景逐像素比：机位不动的镜头一次抠干净 | 容差 / 柔化 / 背景位移 |
| 颜色范围 | HSV 里划个盒子选色：脏绿布、一片天空、一种品牌色 | 目标色 / 色相·饱和·亮度容差 |
| 蒙版清理 | 给蒙版收边 / 扩边 / 填孔 / 去杂点 / 羽化 | 收缩（±32px）/ 羽化 / 去杂点 / 填孔 |
| 去溢色 | 只压边缘彩色反光，不动 alpha | 强度 / 压哪个通道 / 保持亮度 / 只处理半透明 |

### fx.channels（通道，6）

| 节点 | 一句话 |
| --- | --- |
| 分离通道 | 把某条通道变成灰度图（亮度/红/绿/蓝/透明/最亮那条） |
| 合并通道 | 四张灰度图（可取红/绿/蓝/亮度/透明）拼回一张彩色图 |
| 通道混合器 | 每个输出通道 = R/G/B 的加权和，可一键变黑白 |
| 设置透明度 | 用另一张图的某条通道当 alpha（替换 / 相乘 / 相加） |
| 通道错位 | 红往一边、蓝往另一边：色差、老录像带、红蓝 3D |
| 通道交换 | 四个下拉说清「输出通道取谁」 |

### fx.masks（蒙版，6）

| 节点 | 一句话 |
| --- | --- |
| 矩形蒙版 | 位置/尺寸/圆角/羽化/扩张，单位是**画布像素** |
| 椭圆蒙版 | 中心/半径/旋转/羽化，追脸与圆形聚焦 |

| 蒙版柔化 | 羽化 + 扩张/收缩 + 伽马；参数全默认时原样返回 |
| 暗角蒙版 | 径向渐变蒙版，中心留 (0,0) 表示自动取画布中心 |

### fx.tone（色调分离，6）

| 节点 | 一句话 |
| --- | --- |
| 色调分离 Pro | 按亮度（保色相）或 RGB 分档；可平滑台阶、可抖动 |
| 调色板量化 | 亮度每过一档换一个颜色：**硬边不插值**，2 色剪影、4 色海报 |
| 专业色阶 | 输入黑白点 + 伽马 + 输出黑白点，可只作用在一条通道上修偏色 |

| 曲线 | **可拖控制点**的曲线（LUT）：横轴输入亮度、纵轴输出亮度，可只作用于某一条通道 |

| 节点 | 一句话 |
| --- | --- |

| 卡通 | 平涂 + 勾线，两个参数分工明确 |
| 半调网点 | 按亮度调网点（圆点 / 线条），45° 是印刷默认角 |
| 胶片颗粒 | 静态颗粒（同 seed 每帧一样），所以进得了跨帧缓存 |

## 3. 三条给美工的硬约定

### 3.1 `显示 = 蒙版` 是调键的第一步

六个键控/蒙版节点都有 `view`。切到「蒙版」时输出 `(v,v,v,v)`：
**白 = 保留，黑 = 抠掉**，RGB 与 alpha 是同一个值。

为什么两份都写：下游有的节点按 alpha 读（`image.mask` 默认），有的按亮度读。
只写 alpha、RGB 留白，按亮度读的下游会看到「全保留」—— **而且不报错**。

### 3.2 参数归零必须**逐字节**等于原图

`混合 = 0`、`强度 = 0`、`羽化 = 0 且扩张 = 0` 时，C++ 侧直接返回输入的副本，
不是「算一遍再乘 0」。理由很实际：美工调参时会把滑块拖回 0 看原样，
那一刻画面必须真的回去，否则他不敢再拖第二次。
`tests/test_fx_ae_pack.gd` 里每个节点都有一条这样的断言。

### 3.3 单位是像素，不是 0~1

蒙版的位置/尺寸/羽化/收缩全部按**画布像素**。改画布尺寸就重摆 —— 这是明确行为。
只有 `mask.vignette.radius` 是「相对短边一半」的倍数，因为暗角本来就该跟着画幅缩放。

## 3.4 曲线控件与曲线节点的边界（别让它们打架）

曲线是这一批里唯一"参数自己是一张图"的东西：控件负责编辑，节点负责查表。
两者只要各自前进一步就会互相拆台，所以边界写死在这里：

| 谁 | 只许做 | 不许做 |
| --- | --- | --- |
| `tone.curve` 控件 | 编辑点阵、画曲线、**合批**后交给 `ctx["set"]` | 不算像素、不自己缓存 LUT、不在拖动中逐帧写文档 |
| `tone.curves` 节点（C++） | 把点阵采样成 256 级 LUT，逐像素查表 | 不读控件状态、不猜点的语义、不做 UI 侧钳位以外的处理 |

三处踩过/防过的冲突：

1. **写入风暴**：拖动时鼠标每动一像素就 `apply_param` → 换桶 → 整段缓存重建 +
   一条撤销记录。一次拖动几十次重建，看起来就是"一拖曲线整个界面卡住"。
   现在拖动只改本地值并重画，写盘由控件攒到 **0.12 秒**一次尾部写入；
   松手 / 加点 / 删点 / 重置立即 flush（`flush()` 有断言：拖动中 0 次、flush 后 1 次）。
2. **点弹回去**：`sync()` 是"把文档值读回来重画"。拖动未落盘时读回的是旧值，
   点会当场跳回原位。现在 `sync()` 在"有未写改动"时直接跳过。
3. **画的和算的不是一条线**：采样规则曾有三份（控件 / C++ / 文档）。
   现在规则只写一次在文档里（分段线性 + 区间外取端点 + y 钳 0~1），
   并由 `test_fx_ae_pack` 的**逐点对拍**锁住：同一组点，控件 `_sample_at()`
   与算子实际输出最大差 **0.002**。

**参数控件的 kind 是全局命名空间**，所以这里叫 `tone.curve` 而不是 `curve`：
后者是通用词，别的插件（音频包络、遮罩衰减）迟早也想用，谁后注册谁覆盖，
而且停用 `fx.tone` 后别人的 `curve` 参数会变成「未知控件类型」。带插件前缀就没有这个问题。

## 4. 视觉与易用（给美工的那一半）

| 手段 | 在哪 | 解决什么 |
| --- | --- | --- |
| `keycolor` 参数控件 | 抠像节点的「屏幕色 / 目标色」 | 一排常用键色（绿/蓝/天空/白/黑/品红），点一下就换 |
| 「抠像台」面板 | 右侧停靠区 | 在**画面上点一下**取 3×3 平均色写进选中节点；另有「自动选键色」 |
| 默认值 = 拖出来就能看 | 全部 28 个节点 | 节点落地即有合理画面，美工先看效果再调参数 |
| `view` 枚举 | 6 个键控/蒙版节点 | 结果/蒙版一键切，调键不必外接监视器 |
| 中文参数名 + `hint` | 全部 | 悬停即提示「往右会怎样、过了会怎样」 |

节点图标走引擎的**三级回退**：自己的贴图 → 真实渲染样张 → 分类色块。
本套装没画图标，落到第二级「真实样张」——对美工反而更有用。

## 5. 原生实现：为什么不留第二条路

### 5.1 一份实现，删掉旧的那份

这一批最初用 GDScript 写成（0.1.0），随后**整条删除**，换成 `fx.native-kit` 里的 C++。
现在 `plugins/fx.*/` 下没有任何像素循环代码，只有 `nodes.json`、`plugin.json`、两个 UI 脚本。

守住这条的理由：

- 两条路径意味着**只有一条被测**。GDScript 版没有断言、没有预算门禁，
  改一处 C++ 忘了改它，画面就会在"原生没加载"的机器上悄悄不一样；
- 原生缺席时用户的反馈应该是「这个功能不在」，不是「这个功能怎么这么慢」；
- 归属清楚：`diag.blame` 报「算子没有实现」时只可能是原生包的问题，不用猜。

代价如实写在这里：DLL 没编出来 / 架构不符 / 引擎版本不兼容时，**这 28 个节点不可用**。
`diag.blame` 会先报原生库加载失败（归属 `fx.native-kit`），再把缺算子那几条指过去。

### 5.2 ABI 与族类

每个族类只实现一个方法，签名由内核的桥写死（`scripts/graph/kernel/fx_native.gd`）：

```cpp
Dictionary fx_exec(const Dictionary &inputs, const Dictionary &params,
                   const Dictionary &env);
// env 里有：abi / node / type / op / canvas / time / fps / frame / quality / operator_quality
```

`env["op"]` 决定走哪个算子，所以**一个类可以承载一族 5~6 个算子**。
五个族类是五个独立组件：某一族编不出来时只丢那几个算子，不牵连其它四族。

| 类 | 算子数 | 说明 |
| --- | --- | --- |
| `FxKitKey` | 6 | 抠像：色度距离、亮度、差值、颜色范围、蒙版清理、去溢色 |
| `FxKitChannel` | 6 | 通道：RGB/alpha 的取、合、混、错位、交换 |
| `FxKitMask` | 6 | 蒙版：SDF 形状、布尔、亮度转、羽化、暗角 |
| `FxKitTone` | 6 | 色调：分档、调色板、色阶、分离色调、色温、曲线 |
| `FxKitStyle` | 5 | 风格化：Sobel 边缘、浮雕、卡通、半调、颗粒 |

参数在 C++ 侧容错读：颜色可能是 `Color` 或 `"#rrggbb"`，向量可能是 `Vector2` 或 `[x, y]`
（工程文件里存数组），数值可能是 int / float / bool。这些都在 `src/fx_kit_support.h` 里，
一族改一处。

### 5.3 构建

```bash
bash plugins/fx.native-kit/build.sh template_debug     # 产物 native/*.dll，约 30 s
```

前置与 `pixels.native` 相同（godot-cpp 源码 + 一份编好的静态库 + MSVC + Windows SDK），
脚本里写清了三个必带开关（`-Zc:__cplusplus` / `-DTYPED_METHOD_BIND` / `-MT`）。
**不用 SCons**：只有 8 个翻译单元，为它重编整套 godot-cpp 不划算。

### 5.4 预算：几毫秒是可执行的

规则（也写进 `CLAUDE.md` 的不变量）：**任何一个像素算子，在 192×108 下必须 ≤ 3 ms；
做不到就别写成逐像素 GDScript，直接进 GDExtension。**

`tests/test_fx_budget.gd` 把这句话变成门禁（已在 `tools/run_tests.sh` 里）：

| 指标 | 预算 | 本机实测 |
| --- | --- | --- |
| 192×108 单算子 | ≤ 3 ms | 最慢 **2.55 ms**（`channel.combine`，四张图各采样一次） |
| 每像素 | ≤ 135 ns | 最慢 **≈ 122 ns/px**（512×512 下 `channel.combine` 31.9 ms） |
| 29 个算子合计 | — | **31 ms**（参考画布，串行；曲线 1.4 ms） |

口径：每算子跑 5 次取**最小值**（调度抖动只会变慢）；输入是渐变 + 噪点 + 一圈高光，
不用纯色（纯色会让分支预测占便宜）。大图预算按像素同比放大（512² 是 192×108 的 12.6 倍），
所以写的是 ns/px 而不是一个写死的大图毫秒数。

**优化时踩到的两笔大账**（都写在代码注释里，别再踩）：

| 写法 | 代价 | 改法 |
| --- | --- | --- |
| 循环里比较 `String`（`mode == String("red")`） | `channel.extract` 8.6 ms、`set_alpha` 10.4 ms | 循环外转整数枚举 → 0.56 / 0.62 ms |
| 每像素调一次小函数取亮度 | `find_edges` 4.9 ms | 先算亮度平面 + 梯度平面 → 1.6 ms |

## 6. 验收工程：`examples/demo/调色抠像.fxproj`

57 节点 / 35 类型 / 58 边，192×108 / 2 秒，**29 个算子全部被真实求值**。

```
① 主链（决定画面长什么样）
绿幕底 + 椭圆人物 → 专业绿幕抠像 → 蒙版清理 → 设置透明度
      → 换新背景（渐变 → 调色板量化）→ 分离色调 → 专业色阶 → 胶片颗粒 → 输出

② 验收墙（其余算子各接一个预览）
亮度键 · 差值键 · 颜色范围 · 去溢色 · 通道混合器 · 通道错位 · 通道交换
矩形蒙版 · 暗角蒙版 · 亮度转蒙版 · 蒙版柔化 · 蒙版布尔
色调分离 Pro · 色温 · 曲线 · 浮雕 · 半调 · 查找边缘 · 卡通 · 分离通道 · 合并通道
```

> 生成器：`godot --headless --path . --script res://tools/make_lookdev_demo.gd`
> 它是**数据驱动**的两张表（`CHAIN` / `WALL`）。加算子时改表，别手搓 JSON ——
> 这样"新功能进示例工程"就不是一句口号，而是一次改表。

它**不改** `示范工程.fxproj`：那份是性能与回归基线，往里加节点会让基线数字作废。

## 8. 出问题时归谁

| 现象 | 归属 | 判据 |
| --- | --- | --- |
| 拖出来没画面、28 个节点一起失效 | 原生包 | `diag.blame` 报「原生库加载失败」→ 重编 DLL |
| 只有某几个节点失效 | 定义方插件 | 该族的类没绑定成功（`status_fragments` 会报几族在场） |
| 「改了参数没反应」 | 插件 | 先切 `view` 看蒙版变不变；不变就是参数没读到 |
| 蒙版有脏边、吃掉了半透明 | 素材/参数 | 合成前就羽化的素材没有干净边界（见 §6 主链注释） |
| 整工程打不开 | 装配 | `diag.project` 报「节点类型找不到」= 本机没装该插件 |

`diag.blame` 里那 5 条「`fx.*` 的节点，算子由 `fx.native-kit` 提供（已在 inject 声明）」
是**信息**，不是需要动手的问题：它只是把这条依赖关系显式写出来。

## 9. 这一批没做的

- ~~曲线（Curve）~~：**已做**（`tone.curves` + `curve` 参数控件 + 点阵关键帧插值）。
  已知边界：两端点数不同时按跳变处理（不做重采样）—— 拖点前后点数变了，那一段就是硬切。
