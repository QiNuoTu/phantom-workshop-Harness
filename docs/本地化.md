# 本地化与翻译

先说清楚：这个项目里有**两套互不相干**的 i18n。

| | 对象 | 在哪 | 谁维护 |
| --- | --- | --- | --- |
| **① 界面语言包** | 软件运行时显示的文字 | `plugins/*/locales/*.json` + `FxI18nPacks` | 每个插件自己；`core.i18n` 只提供解析与切换 |
| **② 文档翻译** | 仓库里的 Markdown | `README.md` ↔ `README.en.md` | 贡献者，按本文第 3 节的同步规则 |

两者没有共享状态：换界面语言不会改文档，翻译 README 也不需要动代码。

---

## 1. 界面语言包

### 1.1 用户怎么切

三种入口，效果完全一致：

- **设置** → 常规 → **界面语言**（设置项 id `general.locale`，`applies: ui`）
- **菜单** → 窗口 → **切换界面语言**
- **快捷键** `Ctrl+Shift+L`，在已装语言间循环

切换只重建界面文字：**不动文档、不动撤销栈、不重算任何一帧**。播放中切语言也不会掉帧。

语言列表不是写死的，由已启用插件贡献的语言包实时汇总——停用一个插件，它带来的语言
（如果只有它提供）也会从列表里消失。

### 1.2 现在的覆盖情况

| 语言 | 代码 | 来源 | 覆盖 |
| --- | --- | --- | --- |
| 简体中文 | `zh_CN` | **源语言** | 全部（键本身就是中文原文） |
| English (US) | `en_US` | 基座 30 条外壳文案 + 39 个插件各自的包 | 菜单/工具栏/面板/设置/节点名/算子名 |
| 日本語 | `ja_JP` | 基座 24 条外壳文案 + 18 个插件的包 | 外壳完整；插件侧 18/39 |

`--fx-diagnose` 会打印语言包总数（当前 **60** = 基座 3 + 插件贡献的 57 个文件，其中
39 个 `en_US`、18 个 `ja_JP`）。21 个插件目前只有英文包——日文缺的条目会回落到中文原文，
不会显示成空白或键名。

### 1.3 键就是源语言原文

```gdscript
FxI18n.text("画布")                    # → "Canvas"（en_US）
FxI18n.text("已选 {n} 个节点", {"n": 3})  # → "3 nodes selected"
```

这是刻意的设计：**没翻译的文案天然回落成中文原文**，而不是 `missing.key.xxx` 或空字符串。
所以「只翻一半」是合法状态，随时可以增量补齐。

回退链（`FxI18n.chain()`）：

```
当前语言 → 主语言（en_US → en）→ zh_CN → zh
```

找不到键就用键本身（即中文原文）。

### 1.4 插件怎么贡献译文

**推荐：放在自己的目录里。** 文件名就是语言代码：

```
plugins/fx.color/
├── plugin.json
├── plugin.gd
└── locales/
    ├── en_US.json
    └── ja_JP.json
```

```json
{
	"name": "English (US)",
	"entries": {
		"染色": "Tint",
		"用颜色乘/叠加整幅图": "Multiply or add a colour over the whole image"
	}
}
```

也接受扁平写法（手写小包更省事，`name` / `locale` / `order` 三个键会被跳过）：

```json
{
	"染色": "Tint",
	"用颜色乘/叠加整幅图": "Multiply or add a colour over the whole image"
}
```

宿主加载插件时扫描 `locales/*.json` 并登记，**停用/删除插件时译文随贡献一起撤回**——
`core.i18n` 完全不知道这些目录存在，基座也不认识任何插件。

**另一种：代码里返回。** 适合动态生成（比如从表格批量造）：

```gdscript
func locales() -> Array[Dictionary]:
	return [{"locale": "en_US", "name": "English (US)", "order": 90,
		"entries": {"辉光": "Glow"}}]
```

### 1.5 合并顺序与冲突

所有包按 `order` **升序**合并，**后者覆盖前者**：

| 来源 | order |
| --- | --- |
| 基座 `zh_CN`（源语言，`entries` 为空） | 0 |
| 基座 `en_US` / `ja_JP` | 10 / 20 |
| 插件 `locales/*.json` | 默认从 100 起，按文件名顺序 +1；文件里写 `"order"` 可覆盖 |
| 插件 `locales()` 返回值 | 自己给，常用 50 / 90 |

所以插件译文优先级高于基座外壳文案——这是有意的：同一个中文词在不同上下文里可以有不同
译法，谁注册的文案谁说了算。

**键必须全局唯一。** 两个插件用同一个中文原文，会互相覆盖。稳妥做法是给语义容易撞的词
加前缀：

```json
{ "my.glow.半径": "Radius", "my.glow.强度": "Intensity" }
```

### 1.6 给某个插件补一门语言

以给 `fx.color` 补日文为例：

1. 新建 `plugins/fx.color/locales/ja_JP.json`，把 `en_US.json` 的键抄过来，值换成日文。
2. 重建导入缓存（新增文件必须让 Godot 索引到）：
   ```bash
   godot --headless --path . --editor --quit
   ```
3. 自检：
   ```bash
   godot --headless --path . -- --fx-diagnose     # 语言包数量应 +1
   godot --headless --path . --script res://tests/test_platform.gd
   ```
   `test_platform.gd` 里有「语言包是插件贡献」「英文/日文语言包可用」「插件自己的词条
   从它自己的 locales/ 目录读出」三条断言。
4. 界面上切到日本語，肉眼过一遍这个插件的面板与节点。

**只翻一部分完全可以**，缺的回落中文。请不要为了「整齐」把没翻的键删掉——空值会覆盖成空字符串。

### 1.7 给整个软件加一门新语言（例如韩文 `ko_KR`）

1. **声明语言存在**：在 `plugins/core.i18n/fx_i18n_packs.gd` 的 `locales()` 里加一条
   （`entries` 可以先给空字典，名字要写对）：
   ```gdscript
   {"locale": "ko_KR", "name": "한국어", "entries": {}, "order": 30},
   ```
   设置里的下拉框直接读这个列表，加完就出现。
2. **外壳文案**：同文件顶部加 `const KO := {...}`，键与 `EN` 对齐，然后把 `entries` 指向它。
3. **插件文案**：各插件目录下加 `locales/ko_KR.json`。不必一次全加，没加的回落中文。
4. **验证**：`--fx-diagnose` → 包数增加；`Ctrl+Shift+L` 能循环到该语言；跑
   `bash tools/run_tests.sh`（`test_platform` 会检查语言包数量与切换链路）。
5. **命名**：`<语言>_<地区>`，小写下划线（`pt_BR` / `zh_TW`）。地区变体必须是大写地区码。

> 注意：`FxI18n.locale` 是**静态变量**，进程内全局。测试里改过语言记得改回来，
> 否则同进程后续断言会读到别的语言。

### 1.8 什么该翻、什么不该翻

| 该翻 | 不该翻 |
| --- | --- |
| 节点显示名、参数标签、枚举候选 | 节点 id / 算子 id（`image.blur`） |
| 面板标题、菜单项、命令名、按钮 | 设置项 id、命令 id、能力键 |
| 设置项描述、tooltip | 文件路径、插件 id、类名 |
| 皮肤显示名 | 快捷键字符串（`Ctrl+Shift+L`） |
| 状态栏文案（带占位符整体翻） | 日志与错误的技术细节 |

原则：**用户读到的翻，代码里引用的不翻。** 显示名过一遍 `text()`，id 永远原样。

## 2. 文档翻译

### 2.1 文件约定

| 文件 | 语言 | 角色 |
| --- | --- | --- |
| `README.md` | 中文 | **主文档**，先改这里 |
| `README.en.md` | 英文 | 同步翻译，结构与段落一一对应 |
| `docs/*.md` | 中文 | 只维护中文；英文读者看 `README.en.md` + 代码注释 |

两份 README 顶部互链（`<sub>**简体中文** · [English](README.en.md)</sub>`），
改语言切换那一行时两边都要改。

### 2.2 什么时候必须同步英文

改动命中以下任意一条，就必须同一个 PR 里更新 `README.en.md`：

- 新增/移除功能、插件、节点、导出格式
- **任何数字变了**：插件数、节点数、断言数、性能表里的毫秒与倍数
- 安装 / 构建 / 运行命令变了
- 新增文档文件（英文侧至少在「Documentation」列表里加一行）
- 许可或第三方素材说明变了

纯错别字、排版微调可以不同步，但别让两边差距超过一个小版本。

### 2.3 术语表（中 → 英）

翻译时按这张表，别每次换一种说法：

| 中文 | English |
| --- | --- |
| 基座 / 内核 | kernel |
| 插件宿主 | plugin host |
| 贡献点 | contribution point |
| 可逆账本 | reversible ledger |
| 服务代理 | service broker |
| 蓝图 | blueprint |
| 图 / 求值 | graph / evaluation |
| 算子 | operator |
| 节点卡片 | node card |
| 端口 | port |
| 帧缓存 | frame cache |
| 预渲染 / 预取 | prefetch |
| 精确帧 | exact frame |
| 伴随层 / 垫图 | companion layer / stand-in |
| 状态签 | bake badge |
| 缓存色带 | cache strip |
| 标尺 | ruler |

### 2.4 提交规范

```
docs: 补充本地化说明
docs(en): sync README with v0.2 performance numbers
```

英文同步单独提交时用 `docs(en):`，方便 `git log --grep` 找出「英文落后了多久」。

## 3. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 语言包里某条不生效 | JSON 不是 UTF-8 无 BOM，或键里有全角空格 | 用 UTF-8 无 BOM 重存；键必须与源码字符串**逐字符**一致 |
| 加了 `locales/*.json` 但界面没变 | Godot 没索引到新文件 | `--headless --editor --quit` 重建导入缓存 |
| 两条译文互相覆盖 | 两个插件用了同一个中文键 | 给其中一个加前缀（`my.xxx.词`） |
| 某条永远显示中文 | 该插件没提供这门语言，回落源语言 | 正常行为；补包即可 |
| 切换语言后某面板还是旧文字 | 面板把文案缓存在自己的字段里，没订阅 `FxI18n` | 该面板应改为每次 `text()` 取，或在 `subscribe()` 里重建 |
| 翻译后占位符丢了 | 整句被拆开翻 | `{n}` / `{%s}` 必须原样保留，整句一起翻 |
| 截图里出现英文界面 | 测试或截图脚本切过语言没切回来 | 截图前设 `general.locale=zh_CN` |
| `locales/xx.json` 报格式错误 | 顶层既不是 `{name, entries}` 也不是扁平字典（比如写成了数组） | 看诊断输出里 `语言包格式错误：<路径>` |
